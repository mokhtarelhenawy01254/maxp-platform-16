# Company Assistant Telegram Site Scenarios - 2026-05-09

## الخلاصة

قناة تيليجرام للشركة شغالة كنواة مساعد عمليات، وتم توسيع المرحلة الأولى لتقرأ أجزاء تشغيلية أوسع: ملخص الشركة، البحث في الطلبات، تفاصيل الطلب، البحث في المنتجات، ملف العميل، المخازن، حالة المتجر، واتساب، إعلانات فيسبوك، الشحن، التكاملات، قراءة المهام والمحادثات، إنشاء مهمة بعد التأكيد، ذاكرة المحادثة، وفتح محادثة جديدة من منيو تيليجرام.

تحديث الإنتاج بعد أول تشغيل حي: تم تثبيت الـ deterministic routing لطلبات القراءة الواضحة حتى لا يستبدل النموذج أداة منخفض المخزون بأداة المخازن، ولا يحول طلب "تفاصيل آخر طلب" لسؤال توضيحي بدل قراءة آخر طلب. وبعد تشغيل Swan الحي تم تشديد الاختيار مرة أخرى بحيث خطة النظام الحتمية تسبق أي tool plan خاطئ من النموذج في أسئلة المخزون المنخفض وحالة المتجر وملخص الموقع، مع إسقاط أي رد AI يرجع JSON tool-call بدل ملخص طبيعي للمستخدم.

تم إضافة كتالوج سيناريوهات قابل للاختبار في:

- `backend/services/companyAssistant/CompanyAssistantTelegramScenarioCatalog.js`
- `backend/tests/services/companyAssistantTelegramScenarioCatalog.test.js`

الكتالوج الحالي يغطي 39 سيناريو عبر أجزاء الموقع الأساسية:

- مدعوم الآن: 19
- مدعوم جزئيا: 2
- فجوات حالية: 18
- قابل للتشغيل في السيناريوهات الحالية: 20

## نقاط الضعف الحالية

1. **سطح الأدوات اتوسع لكنه لسه مش شامل.** الأدوات الحالية تغطي القراءة التشغيلية الأساسية، لكن لا يوجد بعد أدوات مباشرة للمرتجعات، الفواتير، HR، POS، المشتريات، الأفلييت، التجار، أو RAG بسياسة المصادر.
2. **بعض القراءة ما زالت ملخصات وليست تحليلا كاملا.** ملخص الإعلانات والشحن والتكاملات يقرأ الحالة والأرقام المخزنة، لكنه لا ينفذ diagnosis عميق أو توصية مالية كاملة بدون أدوات تحليل إضافية.
3. **الأفعال محدودة جدا.** الإجراء الوحيد الحقيقي الآن هو إنشاء مهمة، وباقي الأوامر التنفيذية مثل تعديل طلب، نشر إعلان، تعديل مخزون، إرسال حملة، أو تغيير إعداد متجر غير متاحة.
4. **الصلاحيات غير مقسمة بما يكفي.** الموجود حاليا `assistant:read`, `assistant:write`, `tasks:write`, و `*`. نحتاج صلاحيات مجال مثل `orders:write`, `ads:read`, `inventory:write`, `hr:read`, `billing:read`.
5. **لا يوجد deep linking كاف.** الردود لا ترجع روابط مباشرة لصفحات الأدمن أو IDs قابلة للضغط لكل عنصر.
6. **لا يوجد workflow كامل للأوامر الخطرة.** عند إضافة أدوات كتابة، لازم كل إجراء عالي الخطورة يمر بمسودة، ملخص، تأكيد، audit log، وحدود صلاحيات.
7. **الذاكرة تحسنت لكنها ليست CRM.** المساعد يتذكر سياق المحادثة والتصحيحات، لكنه لا يملك timeline موحد لكل عميل أو سجل قرارات لكل عملية.
8. **المرفقات والصوت والصور ليست مفهومة كمدخلات عمل.** لو المستخدم أرسل صورة/فاتورة/voice note من تيليجرام، لا يوجد حاليا pipeline لتحويلها لأداة مفيدة داخل Company Assistant.
9. **لا توجد تنبيهات استباقية من نفس طبقة المساعد.** ممكن المستخدم يسأل، لكن لا توجد قواعد مثل "كل يوم ابعتلي الطلبات المتأخرة" مرتبطة بالمساعد وصلاحياته.
10. **الاختبارات الحية كانت مركزة على النواة.** سيناريوهات runner تغطي الذاكرة والصلاحيات والملخص والمخزون والمهام والسلامة، وتم توسيعها لقراءة الطلبات والمنتجات والمحادثات والمهام. أدوات المرحلة الأولى تحتاج تشغيل حي على قاعدة الإنتاج للتأكد من جودة الردود على بيانات Swan.
11. **تيليجرام Bot له منيو رسمي، لكن Userbot محدود بطبيعة تيليجرام.** بوت API يقدر يعرض commands وkeyboard، بينما userbot لا يملك نفس command menu الرسمي.
12. **النموذج ليس المشكلة الأولى.** وقت الاختبارات كان المسار يستخدم مزود AI نشط من إعدادات النظام، ولاحظنا في الإنتاج `openai/gpt-oss-120b` عبر NVIDIA. حتى لو غيرنا النموذج، بدون أدوات وصلاحيات أوسع سيظل المساعد محدودا.

## خطة إغلاق الفجوات

### المرحلة 1 - قراءة آمنة

- تم تنفيذ أول دفعة قراءة: customers, order details, warehouses/inventory movements, store status, ads summary, WhatsApp status, shipping summary, integrations.
- المتبقي من القراءة الآمنة: landing pages list/details, returns, billing, POS, HR, procurement, affiliate, merchants, RAG/FAQ sources.
- كل أداة قراءة ترجع IDs وروابط أدمن مباشرة وتلتزم بحدود الشركة والصلاحيات.
- إضافة سيناريوهات runner للقراءة التي لا تحتاج بيانات خارجية حساسة.

### المرحلة 2 - مسودات قبل التنفيذ

- أدوات `draft_*` لا تغير بيانات: مسودة إعلان، مسودة حملة تيليجرام، مسودة لاندنج، مسودة رد عميل، مسودة طلب يدوي.
- الرد من تيليجرام يوضح ما سيتم تنفيذه، التكلفة/الأثر، والمخاطر.

### المرحلة 3 - تنفيذ مؤكد ومؤرشف

- أدوات كتابة بتأكيد صريح: تحديث حالة طلب، تعديل ظهور منتج، تحويل مخزون، إرسال حملة، نشر إعلان، فتح تذكرة، إنشاء تنبيه.
- كل تنفيذ يسجل: القناة، المستخدم الخارجي، الشركة، الأداة، المدخلات المختصرة، نتيجة التنفيذ، ووقت التأكيد.

### المرحلة 4 - مساعد استباقي

- قواعد تنبيه من تيليجرام: طلبات متأخرة، مخزون منخفض، فشل واتساب، حملات تصرف بلا نتائج، فواتير قرب الاستحقاق.
- منيو تيليجرام يتوسع حسب صلاحيات القناة: ملخص، طلبات، مخزون، مهام، تنبيهات، محادثة جديدة.

## أوامر التحقق

من `backend/`:

```bash
npm test -- companyAssistantTelegramScenarioCatalog.test.js companyAssistantScenarios.test.js
npm run test:company-assistant:scenarios
```

تشغيل السيناريوهات الحية ضد شركة Swan يحتاج إعدادات الإنتاج أو `.env` الصحيح، ويمكن تفعيل إرسال تيليجرام الحي عبر:

```bash
COMPANY_ASSISTANT_SCENARIO_COMPANY_SLUG=swan COMPANY_ASSISTANT_SCENARIO_LIVE_TELEGRAM_SEND=1 npm run test:company-assistant:scenarios
```
