# 2026-09-03 - Fix Onboarding Hijacking for Non-Store Companies (Harmoney Dental Lab)

## Context
User reported that entering `Harmoney Dental Lab` (`maxp.online/company-dashboard`) displayed the store onboarding checklist card ("خطة أول إطلاق: أضف أول منتج، راجع رابط المتجر، ثبت قناة التواصل، نفذ أول طلب تجريبي"), blocking the entire dashboard, and the sidebar only had "الرئيسية / لوحة التحكم".

## Root Cause
1. In `MainDashboardPage.tsx`, `isNewCompany(dashboard)` evaluated to `true` whenever `orders == 0`, `products == 0`, `customers == 0`, and `revenue == 0`.
2. An early return `if (isEmpty && dashboard) return <OnboardingChecklist ... />` completely hijacked the dashboard and rendered only the store setup checklist, locking out specialty dashboards (like Dental Lab, Medical, etc.) and hiding the mode switcher ("لوحة التخصص والأعمال" / "التطبيقات المثبتة").
3. The store onboarding steps were hardcoded to e-commerce catalog actions even for companies that did NOT have the store app installed (`!hasStoreApp`).

## Resolution
1. Removed the blocking early-return `if (isEmpty && dashboard)` in `MainDashboardPage.tsx`.
2. Guarded `OnboardingChecklist` with `hasStoreApp && isEmpty`, rendering it within the main dashboard flow only for companies that actually have the store app.
3. For dental labs (and other non-store verticals), `SpecialtyDashboardHeader` renders directly with quick action buttons ("استلام حالة معمل", "أطباء الأسنان" linking to `/dental-lab/doctors`) and lab metrics.
4. Added comprehensive regression tests in `MainDashboardPage.onboarding.test.tsx` ensuring `OnboardingChecklist` is never rendered for non-store verticals and does not hijack the page layout.
5. Deployed to production via GitHub Actions and verified live on `maxp.online` (HTTP 200, Nginx dist updated, PM2 cluster healthy).

# 2026-09-03 - Fix Order Details Page Crash (ReferenceError: fetchOrder is not defined)

## Context
Visiting order details `/orders/:id` (e.g. `https://maxp.online/orders/ORD-214164-968`) threw a fatal runtime error and rendered the ErrorBoundary fallback ("حدث خطأ غير متوقع").

## Root Cause
In `OrderDetails.tsx`, `UnifiedShippingCard` was passed `onOrderUpdated={fetchOrder}`, but the hook `useOrderDetails` exports `fetchOrderDetails`. Because `fetchOrder` was undeclared in scope, accessing it threw `ReferenceError: fetchOrder is not defined`.

## Resolution
1. Corrected `onOrderUpdated={fetchOrder}` to `onOrderUpdated={fetchOrderDetails}` in `OrderDetails.tsx`.
2. Verified all translations and types.
3. Prepared for build and deploy to production.

# 2026-09-03 - Fix Storefront Checkout Phone Validation to Support +20 and International Formats

## Context
Store checkout rejected phone numbers entered with the international Egyptian country code (e.g. `+201065642813`).

## Root Cause
1. `CheckoutForm.tsx` had an HTML5 input constraint `pattern="^01[0-9]{9}$"`, causing the browser to flag any number starting with `+` as invalid and block submission.
2. `PaymentSection.tsx` strictly evaluated `/^01\d{9}$/` and blocked the place order button with error message "رقم الهاتف يجب أن يكون رقم موبايل مصري صحيح من 11 رقمًا".
3. `useTierProgress.ts`, `PdpQuickOrderForm.tsx`, and `ProductImageLandingPage.tsx` also hardcoded `/^01\d{9}$/`.

## Resolution
1. Created centralized utility `apps/frontend/src/storefront/utils/phoneValidation.ts` with `isValidStorefrontPhone`, `normalizeEgyptianPhone`, `cleanPhoneNumber`, and `toAsciiDigits` (converting Arabic-Indic digits).
2. Validates Egyptian numbers in local (`01xxxxxxxxx`) and international (`+201xxxxxxxxx`, `+2001xxxxxxxxx`, `00201xxxxxxxxx`, `201xxxxxxxxx`) formats, with spaces or hyphens, as well as valid E.164 international numbers.
3. Removed restrictive HTML5 `pattern` in `CheckoutForm.tsx`.
4. Updated `PaymentSection.tsx`, `useTierProgress.ts`, `PdpQuickOrderForm.tsx`, and `ProductImageLandingPage.tsx` to use the unified validator.
5. Added unit tests in `apps/frontend/src/storefront/utils/__tests__/phoneValidation.test.ts` and updated `checkoutForm.test.tsx`.
6. Pushed to `main`. Deployed to live server (HTTP 200).

## 2026-09-03 - Storefront Instant Page Load & Sub-Second Refresh Optimization
- **Target URL**: `https://ameerelle.maxp.online/product/kashat-anotha-ora7a-tol-alyom`
- **User Request**: Instant reload in the same second ("عايزه اعمل رفريش الاقي حمل ف نفس الثانيه").
- **Root Cause Analysis**:
  1. `StorefrontStudioShell` (admin theme visual editor) in `/src/storefront/studio/` was grouped into `route-storefront`. It imported `StorefrontImagePickerModal` -> `uploadService`. Because `uploadService` was imported by `route-inbox`, Rollup placed it in `route-inbox`.
  2. This created a domino effect: `route-storefront` statically imported `route-inbox` (414 KB) -> `route-dashboard` -> `route-admin` -> all 40+ admin route chunks (HR, Orders, Customers, Tasks, Builder, Templates, etc.), forcing storefront visitors to request 76 JS files!
  3. `i18n-toast.ts` imported `i18n.ts` (1.8 MB) and was included in `app-shared-core`, forcing `app-shared-core` (imported by storefront) to eagerly download `app-i18n`.
  4. `khemet-fashion-eg` was missing from `RUNTIME_THEME_ASSET_LOADERS` in `runtimeThemeResolver.ts`, falling back to `themeResolver` which loaded all 30 theme JSON files (`storefront-theme-presets`, 1.3 MB).
  5. `index.html` loading spinner had an artificial 350ms opacity transition delay in `main.tsx`.
- **Fixes Applied**:
  1. In `apps/frontend/vite.config.ts`:
     - Isolated `/src/storefront/studio/` into `route-storefront-studio`.
     - Grouped `services/uploadService` and `hooks/useDebounce` into `app-shared-core`.
     - Removed `i18n-toast` from `app-shared-core` and created standalone `admin-i18n-toast`.
     - Added `khemet-fashion-eg` to `STOREFRONT_RUNTIME_THEME_MODULE_PATTERN`.
     - Added `storefront-themes`, `app-i18n`, `route-storefront-studio` to `STOREFRONT_DEFERRED_PRELOAD_CHUNKS`.
  2. In `apps/frontend/src/bootstrap/AdminAppBootstrap.tsx` & `main.tsx`:
     - Moved `loadAdminShellAssets` (`index.css`, `app-dashboard.css`, `i18n`) exclusively into `AdminAppBootstrap.tsx`.
     - Updated `removeLoadingScreen` to support instant removal (`removeLoadingScreen(true)`) for storefront visits, eliminating the 350ms delay.
  3. In `apps/frontend/src/storefront/engine/runtimeThemeResolver.ts`:
     - Added `khemet-fashion-eg` directly to `RUNTIME_THEME_ASSET_LOADERS` so it loads only its single lightweight ~30KB JSON file instead of the full 30-theme registry.
  4. In `apps/frontend/src/storefront/blueprints/compiler.ts`:
     - Decoupled `DEFAULT_STOREFRONT_THEME_ID` import from `../themes` to `../engine/themeDefaults`.
- **Verification**:
  - Live benchmark via Puppeteer on `https://ameerelle.maxp.online/product/kashat-anotha-ora7a-tol-alyom`:
    - First Contentful Paint (FCP): **664ms** (down from 2.8s)
    - Product Details & Buybox Visible (H1 painted): **800ms** (sub-second, down from 4.8s)
    - Total JS requests on refresh: **23** (down from 76, 70% reduction)
    - Material UI (`vendor-mui`), Admin routes (`route-inbox`, `route-dashboard`, `route-hr`), and i18n (`app-i18n`) are **0% requested** by storefront visitors.
