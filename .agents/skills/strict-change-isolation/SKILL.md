# 🛡️ Strict Change Isolation Skill (Zero Blast-Radius Law)

## 🎯 الهدف الأساسي (Core Mandate)
**"أي حاجة تتعدل في أي حتة في الموقع ما تسمعش نهائي في أي حتة تانية."**
تفرض هذه المهارة عزلًا هندسيًا تامًا (100% Blast-Radius Containment) عند إجراء أي تعديل برمجي أو تصميمي في منصة MaxP، سواء في الواجهة الأمامية (Frontend)، الخادم الخلفي (Backend)، أو قاعدة البيانات، لضمان عدم حدوث أي تأثيرات جانبية (Side Effects) أو كسر غير مقصود في أي شاشة أو ميزة أخرى.

---

## 🚨 القواعد الذهبية السبعة للعزل الصارم (The 7 Laws of Zero Side-Effects)

### 1. فحص مدى التأثير قبل لمس أي ملف (Mandatory Pre-Edit Reference Audit)
قبل تعديل أي دالة، مكون (Component)، هوك (Hook)، خدمة (Service)، أو ملف CSS:
- **حظر التعديل الأعمى:** يُمنع منعًا باتًا تعديل أي ملف مشترك قبل البحث عن جميع أماكن استخدامه (`grep` / `find references`).
- إذا كان الملف مستخدمًا في **أكثر من شاشة أو مكان واحد**:
  - لا تغيّر السلوك الافتراضي (Default Behavior) أبدًا.
  - إما أن تمرر خاصية اختيارية جديدة (`optional prop / parameter`) بقيمة افتراضية تحافظ على السلوك القديم 100% في كل الأماكن الأخرى، أو تفصل منطق الشاشة المستهدفة في مكون/دالة مستقلة خاصة بها.

### 2. قاعدة "الفصل بدلاً من التعديل المشترك" (Fork/Specialize Over Mutating Shared Components)
- إذا طلبت شاشة معينة تعديلًا جذريًا في شكل أو سلوك مكون مشترك (مثل جدول، نافذة منبثقة، هيدر، أو كارت منتج):
  - **ممنوع** تعديل المكون العام في `components/common/` أو `components/ui/` بحيث يتغير شكله في باقي صفحات الموقع.
  - **الحل الإلزامي:** أنشئ نسخة مخصصة محليًا داخل مجلد الشاشة نفسها (مثلاً `pages/<feature>/components/`) أو غلّفها (Wrapper) بحيث يقتصر التغيير على الصفحة المطلوبة فقط دون المساس بباقي الموقع.

### 3. عزل التصميم والـ CSS (Strict CSS & Layout Containment)
- **حظر تعديل الـ CSS العام:** يُمنع تعديل القواعد العامة في `index.css`، `App.css`، أو إعدادات `tailwind.config.js` الأساسية لحل مشكلة تخص شاشة واحدة.
- **عزل الحاويات (Layout Isolation):** أي تعديل في أبعاد أو هوامش شاشة معينة يجب أن يتم عبر الكلاسات المباشرة لجذر تلك الشاشة فقط، ولا يجوز تعديل `Layout.tsx` أو `Sidebar` العام بطريقة تغير أبعاد أو تمرير (Scroll) الشاشات الأخرى.

### 4. عزل الحالة والبيانات في الواجهة الأمامية (State, Context & Storage Isolation)
- **حظر تلويث الـ Context العام:** لا تقم بتعديل شكل البيانات أو طريقة عمل `AuthContext`، `CompanyContext`، أو `SocketContext` لخدمة ميزة فرعية واحدة.
- **عزل مفاتيح التخزين المحلي (`localStorage` / `sessionStorage`) ومفاتيح الكاش (`React Query / SWR`):**
  - يجب أن يكون لكل شاشة بادئة مفاتيح (Namespace Prefix) خاصة بها (مثل `dental_bench_filter_v1` بدلاً من `filter` أو `selected_tab`) لمنع تداخل الحالة عند التنقل بين الصفحات.

### 5. توافق العقود الخلفية والـ APIs (Backend API Backward Compatibility)
- عند تعديل أي مسار API أو `Service` في الـ Backend لخدمة صفحة معينة:
  - **ممنوع حذف أو تغيير اسم أي حقل** في الـ Response JSON يعتمد عليه مكان آخر في الموقع أو تطبيق الموبايل/الديسكتوب.
  - **ممنوع تغيير شروط الاستعلام الأساسية** لدالة مشتركة في `services/`؛ إذا كانت الصفحة تحتاج فلترة أو منطقًا مختلفًا، أضف باراميتر اختياري صريح (بقيمة افتراضية لا تغير السلوك القديم) أو أنشئ Endpoint/دالة مستقلة خاصة بهذه الصفحة فقط.

### 6. عزل الشاشات والأخطاء (Modular Screen & Error Boundary Isolation)
- كل شاشة أو تبويب فرعي مستقل في ملفه الخاص وحالته الخاصة (وفق قاعدة Modular Independent Screens).
- أي خطأ برمجي أو حالة فارغة في شاشة لا يجوز أن يوقف أو يؤثر على أي شاشة مجاورة.

### 7. التحقق الإلزامي بعد التعديل (Post-Edit Blast-Radius Verification)
قبل اعتماد أي تعديل وعمل `git commit`:
1. نفّذ `git diff` لمراجعة كل سطر تم تغييره.
2. تأكد أن قائمة الملفات المعدلة (`git status`) تقتصر **حصريًا** على الملفات الخاصة بالمهمة المطلوبة، وعدم وجود أي تعديلات شاردة في ملفات أخرى.
3. إذا تم لمس أي ملف مشترك (مثل `routes` أو `types` أو `api.ts`)، تحقق من أن جميع الإضافات هي **إضافات غير كاسرة (Additive & Non-Breaking)** بنسبة 100%.

## 📋 قائمة الفحص السريعة قبل أي تعديل (Pre-Flight Isolation Checklist)

```markdown
- [ ] هل الملف الذي سأعدله مستخدم في شاشة أخرى؟ (تم الفحص بـ grep)
- [ ] إذا كان مشتركًا: هل عزلت التعديل في الشاشة المستهدفة فقط أو استخدمت باراميتر اختياري لا يغير السلوك القديم؟
- [ ] هل تجنبت تعديل ملفات الـ CSS العامة أو الـ Layout العام؟
- [ ] هل عقود الـ API والـ Response JSON متوافقة 100% مع كل الشاشات الأخرى؟
- [ ] هل `git diff` يؤكد أن التعديل محصور في النطاق المطلوب فقط بدون أي أثر جانبي؟
```
