### 2. Finding: `/api/v1/auth/companies` is tenant-scoped (latent bug)
- **Symptom:** For `swan@h2m.com` the endpoint returns only the CURRENT company (1 of 4 memberships: Swan, Tala Store, red line, TATO).
- **Root cause (proven on server):** `2026 Auto-Tenant Isolation` AST extension in `services/sharedDatabase.js` injects `companyId` into top-level `findMany` on models with a `companyId` column — `UserCompany` is NOT in `GLOBAL_MODELS`, so `getUserCompanies` gets `where.companyId = <current company>` and can never list the user's other companies.
  - Proof: same query with `tenantContext.run(null, …)` → 4 rows; with Swan context → 1 row.
  - Same class as the earlier `Role` fix (commit `d3f82757c` added `Role` to `GLOBAL_MODELS`).
- **Impact today:** low — no frontend/desktop/mobile consumer calls `/auth/companies` (only a backend debug script). The UI company switcher uses `/auth/me` (`userCompanies` include — unaffected). Also note `setDefaultCompany`'s `userCompany.updateMany({ where: { userId } })` is silently scoped by the same injection.
- **Proposed fix (not yet applied):** add `'UserCompany'` to `GLOBAL_MODELS` in `apps/backend/services/sharedDatabase.js` (+ audit of userCompany update/delete call sites for explicit companyId filters).
