# الخطة الشاملة — نطاق لكل شركة + تطبيق ولي الأمر (Multi-Tenant Portal & App)

**الحالة:** مسودة للاعتماد · **التاريخ:** 2026-11-10 · **المرجع:** أكونت `codetreps` على `maxp.online`

---

## 1) السؤال الأساسي والجواب

> هل بوابة ولي الأمر والمدرس المفروض تفتح على **السبدومين الخاص بالشركة**؟

**أيوه — وده الصح، وفيه 3 أسباب:**

1. **العزل:** بيانات كل شركة تفضل على نطاقها، والروابط اللي تتبعت لأولياء الأمور تحمل هوية المركز مش هوية المنصة.
2. **الثقة:** ولي الأمر اللي بيدفع فلوس لازم يشوف `codetreps.maxp.online` مش `maxp.online`.
3. **التطبيق:** الـPWA/التطبيق بياخد الاسم والأيقونة من النطاق → "تطبيق الشركة" من غير بناء نسخة لكل عميل.

### الوضع الحالي في الكود

| المكوّن | الحالة |
|---|---|
| `subdomainMiddleware` — يحوّل `<slug>.maxp.online` → `req.company` | ✅ **موجود** |
| دعم دومين مخصص (`company.com`) | ✅ موجود (`docs/CUSTOM_DOMAIN_SETUP.md`) |
| استخدام النطاق في بوابة المدرس/ولي الأمر | ❌ **مش موجود** — البوابتان شغالين على النطاق الرئيسي فقط |
| براندنج البوابات (شعار/ألوان الشركة) | ❌ ناقص |
| PWA / manifest لكل شركة | ❌ ناقص |

### 🔴 ثغرة لازم تتصلح قبل أي حاجة (P0)

تسجيل دخول **ولي الأمر** و**المدرس** بيدوّر على الحساب **بدون فلترة بالشركة**:

```js
// educationParentAuthController.login — لا يوجد companyId في الـ where
prisma.customer.findFirst({ where: { OR: [{ email }, { phone }, { phone2 }] } })
```

لو نفس رقم الموبايل/الإيميل موجود في شركتين → المستخدم يدخل على **الشركة الغلط**. ولما البوابات تبقى على سبدومين، ده لازم يتقفل فورًا.

## 2) المبدأ المعماري

```
codetreps.maxp.online            ← نطاق الشركة
   ├── /parent/login             ← بوابة ولي الأمر (براندنج الشركة)
   ├── /teacher/login            ← بوابة المدرس
   ├── /parent/activate          ← تفعيل الحساب
   └── /app (manifest + install) ← تثبيت "تطبيق الشركة" (PWA)

maxp.online                      ← المنصة (لوحة إدارة، تسويق، سوبر أدمن)
```

- كل طلب على السبدومين → `req.company` → كل استعلام يتفلتر بـ `companyId` تلقائيًا.
- النطاق الرئيسي يفضل شغال (fallback) عشان محدش يتقفل بره.

## 3) المراحل

### P0 — أساس العزل والنطاق ⏱ 3–4 أيام

| المهمة | التفاصيل |
|---|---|
| 1 | فلترة تسجيل الدخول بالشركة (ولي الأمر + المدرس): النطاق أولًا، ثم `companyId` لو النطاق رئيسي |
| 2 | الحساب موجود في أكتر من شركة؟ → اختيار الشركة أو رسالة واضحة |
| 3 | `req.company` يتحقن في البوابات (بدل الاعتماد على `user.companyId` فقط) |
| 4 | اختبار عزل: نفس الرقم في شركتين → كل واحد يدخل على شركته |

**معيار القبول:** مستخدم مسجّل في شركتين يفتح `A.maxp.online` → يشوف بيانات A فقط، و`B.maxp.online` → بيانات B فقط.

### P1 — براندنج البوابات ⏱ 2 أيام

| المهمة |
|---|
| شعار + اسم + ألوان الشركة في `ParentLayout` و`TeacherLayout` |
| Splash/شاشة الدخول باسم المركز |
| عنوان الصفحة (title) + favicon حسب الشركة |
| احتياطي: لو مفيش شعار → اسم الشركة نصيًا |

**معيار القبول:** فتح `codetreps.maxp.online/parent/login` يعرض اسم وشعار CodeTreps بدون أي ذكر لـ MaxP في الواجهة.

### P2 — PWA لكل شركة ⏱ 2–3 أيام

| المهمة |
|---|
| `manifest` ديناميكي لكل شركة (`/manifest.webmanifest?c=<slug>`) بالاسم والأيقونة والألوان |
| أيقونات مولّدة من شعار الشركة (192/512/maskable) |
| Service Worker موجود (`sw.js`) — يحتاج تسجيل لكل نطاق |
| صفحة/زر "ثبّت التطبيق" + تعليمات iOS |
| شاشة offline بسيطة |

**معيار القبول:** من موبايل، فتح نطاق الشركة → "إضافة إلى الشاشة الرئيسية" → أيقونة واسم الشركة، ويفتح fullscreen، وبإشعارات لاحقًا.

### P3 — قشرة تطبيق ولي الأمر (Capacitor) ⏱ 3–4 أيام

بنفس فكرة التطبيق الحالي (`server.url` + تحديث + Splash):

| المهمة |
|---|
| مشروع Capacitor بـ `appId: online.maxp.parent` ويحمّل `/parent/login` |
| Deep Link: `maxp.online/i/<slug>` → يفتح التطبيق على شركة محددة |
| نسخة/تحديث مستقل (`/api/v1/app/version/parent` + `/download/maxp-parent.apk`) |
| أيقونة/سبلاك/اسم "MaxP أولياء الأمور" |

**معيار القبول:** APK يفتح على بوابة ولي الأمر، ولينك `/i/codetreps` يفتحه على شركة CodeTreps.

### P4 — الإشعارات ⏱ 4–5 أيام

| المهمة |
|---|
| FCM للـAPK + Web Push للـPWA |
| Backend: تخزين توكن الجهاز مربوط بالمستخدم والشركة |
| أحداث: حصة غدًا · غياب · مستحقات · باقة قربت تخلص · رصيد محفظة |
| شاشة تفضيلات إشعارات لولي الأمر |

**معيار القبول:** جدولة حصة → إشعار يوصل على موبايل ولي الأمر خلال دقيقة، وبنص عربي سليم.

### P5 — White-label APK (باقة مدفوعة) ⏱ 4–6 أيام + عملية لكل عميل

Aيمن لكل شركة (`package` + أيقونة + توقيع + نشر على نطاقها أو Play).
**مش شرط للنجاح** — نفعّلها لما يبقى فيه عميل بيدفع كفاية.

## 4) الترتيب الزمني

| الأسبوع | التسليم |
|---|---|
| 1 | **P0 + P1** — عزل + براندنج (البوابات تبقى "بتاعة الشركة" على نطاقها) |
| 2 | **P2** — PWA لكل شركة (تطبيق من غير متجر) |
| 3 | **P3** — قشرة تطبيق ولي الأمر + Deep Link |
| 4 | **P4** — إشعارات |
| لاحقًا | P5 حسب الطلب |

---

## 5) قرارات مطلوبة من العميل

1. **شكل النطاق:** `<slug>.maxp.online` (جاهز فورًا) ولا **دومين خاص** بالمركز (`codetreps.com`)؟
2. **الشعار والألوان** الرسمية للمركز (SVG/PNG + كود اللون).
3. **اسم التطبيق** على شاشة الموبايل — "Code Treps" ولا "Code Treps — أولياء الأمور"؟
4. **مين يستقبل الإشعارات**: ولي الأمر فقط، ولا المدرس كمان؟
5. **White-label APK**: مطلوب الآن ولا لاحقًا كباقة؟

## 6) المخاطر

| الخطر | التخفيف |
|---|---|
| كسر روابط قديمة (ماكس على النطاق الرئيسي) | fallback كامل على `maxp.online` + تحويل تدريجي |
| تكرار الحساب بين شركتين | شاشة اختيار شركة + سجل تدقيق |
| شهادات SSL للسبدومينات | شهادة wildcard `*.maxp.online` — لازم تتأكد من السيرفر |
| Service Worker قديم يعرض نسخة قديمة | versioning + skipWaiting |
| إشعارات iOS في PWA | تنبيه واضح إنها تحتاج iOS 16.4+ |

## 7) خارج النطاق (متعمد)

- بناء تطبيق Native منفصل لكل شركة على المتاجر.
- تغيير شكل لوحة إدارة المنصة.
- دفع داخل التطبيق (Apple/Google Pay) — يبقى مرحلة تانية.

## 8) المخرجات

1. `subdomain` يشتغل على البوابات + عزل مؤكد باختبار.
2. بوابات بعلامة كل شركة على نطاقها.
3. PWA قابل للتثبيت لكل شركة برابط واحد.
4. APK لولي الأمر + Deep Link لكل شركة.
5. إشعارات مربوطة بالأحداث.
