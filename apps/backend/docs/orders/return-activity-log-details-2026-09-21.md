# توضيح سجل النشاط في طلبات الإرجاع ومسؤولية المراجعة - 2026-09-21

## المشكلة
كان سجل النشاط في شاشة تفاصيل طلب الإرجاع (`ReturnDetailsModal.tsx`) يعرض فقط الاسم الأول للمستخدم ("قام Swan بهذا الإجراء") مع عرض محتوى الإجراء ككود JSON فارغ `{}` بسبب تسجيل كائن فارغ في الباك إند عند المراجعة (`REVIEWED`)، ودون توضيح ما تم تحديده أثناء المراجعة (الجهة المسؤولة، سبب الإرجاع، شركة الشحن، نوع المرتجع، تكلفة الشحن، صافي التسوية، والملاحظات).

## الحل والتطوير

### 1. الباك إند (`returnController.js`)
- تحديث `updateReturnRequest`:
  - عند المراجعة (`isReviewed && !oldRequest.isReviewed`): حفظ تفاصيل المراجعة كاملة في `details` (الجهة المسؤولة، سبب الإرجاع، شركة الشحن، نوع المرتجع، تكلفة الشحن الراجع، صافي التسوية، وملاحظات الإدارة والعميل).
  - عند تعديل طلب مراجع لاحقاً: تسجيل لوج `UPDATED` مع تفاصيل الحقول التي تم تعديلها وقيمتها السابقة والجديدة.
  - عند تعديل الملاحظات الإدارية: تسجيل نص الملاحظة السابقة والجديدة بدلاً من النص الثابت.
- تحديث `getActivityLog`:
  - جلب بيانات المستخدم كاملة (`firstName`, `lastName`, `email`, `role`).
  - دعم التوافقية السابقة (Backward Compatibility): إذا كان السجل التاريخي `REVIEWED` وكانت تفاصيله `{}`، يتم استخلاص بيانات المراجعة تلقائياً من واقع طلب المرتجع المرتبط لعرضها فوراً للمستخدم.

### 2. واجهة المستخدم (`ReturnDetailsModal.tsx`)
- إعادة تصميم كاملة لتبويب "سجل النشاط":
  - توضيح دقيق للفاعل: الاسم الكامل، شارة الدور الوظيفي (مالك الحساب / مدير / مشرف / موظف)، البريد الإلكتروني، وأيقونة الأفاتار.
  - في حالة النظام الآلي: شارة "النظام الآلي" مع أيقونة روبوت توضح السبب التلقائي (مثل تحديث حالة الشحنة إلى RETURNED).
  - عناوين عربية واضحة للإجراءات (`مراجعة واعتماد المرتجع`، `إنشاء طلب إرجاع تلقائي`، `تسجيل محاولة تواصل`، `تغيير حالة المرتجع`، `تعديل بيانات المرتجع`، إلخ) مع ألوان وحالات دلالية.
  - بطاقة تفاصيل مراجعة منظمة تعرض الجهة المسؤولة، السبب، شركة الشحن، نوع المرتجع، التكلفة، وصافي التسوية، بدون ظهور أي كتل `{}` أو JSON خام.
  - تعريب أزرار الفلترة حسب نوع النشاط مع إظهار عدد الأنشطة لكل نوع.
