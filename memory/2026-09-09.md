## Task: Fix Facebook Inbox Images in Mobile App / Mobile View
- **Company Tested**: Ameerelle (`ahmedfares61994@gmail.com`)
- **Reported Issue**: Images in Facebook Inbox (`https://maxp.online/facebook-inbox`) appeared as broken icons with text "صورة", quoted reply thumbnails were blank/broken, and customer avatar was broken in mobile mode.

### Root Causes Identified
1. **Local Upload Resolution in `proxyImageController.js`**:
   - Quoted replies (`/api/proxy-image?messageId=...`) resolved `message.content` which was `/uploads/products/gallery-....webp`.
   - Node native `fetch(candidateUrl)` with relative path threw `TypeError: Failed to parse URL` (`ERR_INVALID_URL`), returning `500 Internal Server Error`.
2. **Cross-Origin Resource Policy (CORP) Blocking in Mobile App**:
   - In Capacitor/mobile app, origin is `https://localhost` or `capacitor://localhost`.
   - Helmet defaulted to `Cross-Origin-Resource-Policy: same-origin`.
   - Both `/uploads/*` and `/api/proxy-image` returned `same-origin`, causing the Android Chromium webview to strictly block cross-origin image loads with an `error` event.
3. **Customer Avatar Proxy & Fallback**:
   - `resolveFreshCustomerAvatarUrl` did not select `customer.avatar` and lacked fallback handling when Facebook tokens expired or Graph API failed.
   - Frontend `FacebookInbox` header avatar, `ConversationItem`, and `CustomerProfile` lacked `onError` handlers, displaying browser broken image icons.

### Solution Applied
1. **Backend `proxyImageController.js`**:
   - Added `resolveLocalUploadFilePath` to check `uploadRoots` and serve local upload files directly from disk via `fs.promises.readFile`, with Sharp optimization/transform support.
   - Added safe fallback in `fetchRemoteAsset` to prefix relative URLs with `http://127.0.0.1:${PORT}` to avoid `ERR_INVALID_URL`.
   - Explicitly added `Cross-Origin-Resource-Policy: cross-origin` and `Access-Control-Allow-Origin: *` to `sendRemoteResponse`, `sendInlineAssetResponse`, and `sendLocalFileResponse`.
   - Updated `resolveFreshCustomerAvatarUrl` to include `customer.avatar` in database select and fall back gracefully.
2. **Backend `server.js`**:
   - Updated Helmet config: `crossOriginResourcePolicy: { policy: "cross-origin" }`.
   - Set `Cross-Origin-Resource-Policy: cross-origin` and `Access-Control-Allow-Origin: *` on `/uploads`.
3. **Backend `routes/proxyRoutes.js` & `middleware/globalSecurity.js`**:
   - Added `HEAD` routes to public whitelist and CORP cross-origin middleware to proxyRoutes.
4. **Frontend**:
   - Added `onError` fallback handlers to customer avatar in `FacebookInbox.tsx`, `ConversationItem.tsx`, and `CustomerProfile.tsx` (switches to letter avatar fallback seamlessly if image fails).
   - Added retry logic in `MessageBubble.tsx` for proxied images.

### Verification
- Tested via Node script with `Origin: https://localhost`:
  - Quoted reply proxy image: 200 OK (`image/webp`, CORP `cross-origin`)
  - Product image upload: 200 OK (`image/webp`, CORP `cross-origin`)
  - Customer avatar proxy: 200 OK (`image/jpeg`, CORP `cross-origin`)
- Synced to production server (`srv974554.hstgr.cloud`), reloaded PM2 `maxp-backend`, and pushed to GitHub `mokhtar267/maxp-platform-6` (commit `d3f88b8f5`).

## Task: MaxP Academy Two-Tier Architecture (Global Platform Courses vs Company Private Courses)
- **Problem**: Previously, all courses in `AcademyCourse` were strictly isolated by `companyId`. When MaxP platform administration created an official flagship course (e.g. Media Buyer 29 lessons or platform onboarding), tenants/companies could not see or enroll in it because their tenant `companyId` differed.
- **Architectural Solution (Two-Tier Model)**:
  1. **Prisma Schema (`academy.prisma`)**:
     - Added `isGlobal Boolean @default(false)` with `@@index([isGlobal])` to `AcademyCourse`.
     - Regenerated Prisma Client (`npm run schema:generate`).
  2. **Backend Service (`academyService.js`)**:
     - `createCourse` & `updateCourse`: Support `isGlobal`.
     - `getPublishedCatalog`: Query courses where `{ isPublished: true, OR: [{ companyId }, { isGlobal: true }] }`.
     - `getCourseOutlineWithProgress` & `enrollStudent`: Check `OR: [{ companyId }, { isGlobal: true }]` so users from any company can access outline, enroll, and stream lessons.
     - Enrollment detection relaxed to recognize active enrollments across tenant boundaries for global courses.
  3. **Backend Controller (`academyController.js`)**:
     - Guarded `isGlobal` flag so only `SUPER_ADMIN` role can create or toggle platform-wide global courses; stripped for non-admins.
  4. **Frontend (`academyApi.ts`, `AcademyCatalogPage.tsx`, `AcademyCoursesPage.tsx`, `AcademyCourseEditorPage.tsx`)**:
     - Added `isGlobal?: boolean` to TypeScript interfaces.
     - Catalog Page: Added amber badge `كورس رسمي من MaxP` with shield icon for global courses.
     - Courses Management: Added `كورس عام على المنصة` badge in table/cards.
     - Course Editor Settings Modal: Added switch toggle `كورس عام على مستوى المنصة (Global)` with explanatory text.
- **Verification**:
  - `npm run schema:generate`: 0 errors.
  - `npm run build --prefix apps/frontend`: 0 errors (built in 1m 22s).
  - Pushed to `mokhtar267/main` (commit `bd252f26`).
