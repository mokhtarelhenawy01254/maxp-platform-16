# Business Goals System

## Overview

The goals feature now acts as a business operations goal system rather than an HR-only page. The main experience lives under the Business area and supports project goals, employee goals, department goals, and company goals.

## Goal Hierarchy

- A goal can have a `parentGoalId`, which allows parent/child goal trees.
- A project goal can roll down into employee goals through assignments.
- An employee goal can roll down into daily goals when `autoGenerateDaily` is enabled.
- Progress rolls upward from child goals to their parent goal, so daily updates affect the employee goal and then the project goal.

## Daily Goal Generation

- Daily goals are distributed across configured company workdays, not every calendar day.
- The system uses HR settings workdays when splitting an employee target across the selected date range.
- Daily goals are ensured on attendance check-in so the employee always has today's target available before checkout.
- Auto-generated daily goals are marked separately from manually created goals.

## Attendance Flow

- On check-in, the backend ensures today's daily goals for the employee.
- On the employee attendance page, today's goals are shown in a dedicated card.
- On checkout, if daily goals exist, the employee is prompted to submit the achieved value for each goal.
- Each submitted daily update calls the goal progress API, then the regular attendance checkout continues.

## Tasks and Goal Linkage

- Tasks can optionally link to a goal through `goalId`.
- Tasks now support different measurement styles:
  - `TIME`
  - `COUNT`
  - `VALUE`
- Metric-based tasks can store:
  - `metricUnit`
  - `metricTargetValue`
  - `metricCurrentValue`
- This supports operational tasks such as order confirmation, where success is measured by completed units rather than elapsed time.

## UI Surface

- Goals routes are available at:
  - `/goals`
  - `/goals/new`
  - `/goals/:id`
- Legacy HR goal routes redirect into the new business-oriented routes.
- The sidebar entry has been moved from HR into the Business tasks area.

## Current Assumption

The current implementation assumes that daily employee targets should be spread across scheduled workdays, then guaranteed again at attendance check-in. This keeps the plan stable at the monthly level while still matching the day-to-day attendance workflow.
