# 2026-09-21

## Summary of Accomplishments

### 1. Order Return Display & Return Reason (تفاصيل الطلب وقائمة الطلبات)
- **Problem**: On the order details page (`/orders/ORD-...`), when an order was returned, it wasn't prominently displayed, and the specific return reason (سبب المرتجع), shipping captain/branch notes, and return origin were not clearly exposed. Additionally, in the main orders table, guest orders returned via Turbo (`returned_to_company`) were showing as "تجهيز معلق" (PENDING) instead of "مرتجع" because `effectiveCodeForGuest` only checked prep metadata.
- **Root Cause & Fixes**:
  - **Backend (`apps/backend/routes/orders.js`)**:
    - Exposed `turboShipmentStatus`, `turboReturnReason`, `turboDelayReason`, and `turboTrackingNumber` in both `formattedRegularOrders` and `formattedGuestOrders`.
    - Added twin order lookup (`const twin = regularTwinsByNumber.get(twinKey)`) so guest orders inherit carrier return reasons and tracking.
    - Updated `effectiveCodeForGuest` to detect carrier return codes (`returned_to_company`, `returned_received`, `returned_resent`, `returned_missing`, `returned_destroyed`, `5`, `10`, `11`, `12`, `20`) and map them directly to `'RETURNED'`.
    - Included `returnRequests` relation in `GET /simple/:orderNumber`.
  - **Backend (`apps/backend/services/orderService.js` & `turboStatusSyncService.js`)**:
    - Updated `updateOrderStatus` and `updateGuestOrderStatus` to allow in-place notes/reason updates when status is unchanged.
    - Updated `turboStatusSyncService.js` to pass explicit `return_reason` into order notes.
  - **Frontend Components**:
    - `src/pages/orders/utils/returnHelper.ts`: Exported `isTurboReturnStatus`, `isReturnStatusCode`, `isOrderReturned`, `getOrderReturnDetails`, and `COMMON_RETURN_REASONS`.
    - `src/pages/orders/components/OrderReturnCard.tsx`: Machined rose border card (<210 lines) displaying return type, reason, delay notes, shipping captain, and branch details.
    - `src/pages/orders/components/OrderHeader.tsx`: Unmissable return pill in header next to status selector.
    - `src/pages/orders/components/OrderActivityLog.tsx`: Added dedicated `ArrowPathRoundedSquareIcon` with rose/amber badge and explicit `سبب المرتجع: {reason}` formatting for return events in the activity timeline.
    - `src/pages/orders/Orders.tsx`: Updated `getUnifiedStatusDisplay` to prioritize carrier return statuses (`isTurboReturnStatus`) so that returned orders reflect `مرتجع` directly in the orders list.
    - `src/pages/orders/components/OrdersTable.tsx`: Displayed `↩ {turboReturnReason}` under the status column and verified return reason badges in the table.
    - `src/pages/orders/components/OrdersMobileList.tsx`: Added return reason display in mobile list layout.
- **Live Verification**:
  - Tested on production `https://maxp.online` with account `swan@h2m.com`.
  - Confirmed on `ORD-280103-339` (prominent return card with reason `الرقم لا يرد نهائيا`, delay note `الرقم مغلق`, captain & branch info).
  - Confirmed in orders table that `ORD-280103-339` shows `مرتجع` with reason badge.
  - Screenshots saved to artifacts: `order_280103_339_verified.png`, `order_651524_297_verified.png`, `orders_table_returns_verified.png`.

### 2. Turbo Support Tickets Pagination & Chronological Sorting
- **Problem**: In `/tickets`, pagination disappeared and newer tickets were overshadowed by older tickets receiving automated survey updates.
- **Fix**:
  - Extracted `result.meta` in `ticketService.js` to restore accurate total count (2500+ tickets, 168+ pages) and active pagination controls.
  - Enhanced sorting to prioritize: Unread tickets -> Open/In-progress -> Highest ticket ID / newest created -> Updated timestamp.
  - Added helpful empty state in `TurboTicketListPanel.tsx` with one-click navigation to view all statuses.
