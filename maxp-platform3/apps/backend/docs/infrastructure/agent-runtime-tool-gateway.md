# Agent Runtime Tool Gateway

The CEO Agent now treats model output as a plan, not as UI text, when the output contains internal tool-call syntax.

- `services/aiAgent/agentToolCallParser.js` parses legacy `CALL_TOOL`, OpenAI-compatible native names, and leaked DSML-style text such as `tool_calls` / `agenttool__...`.
- `services/aiAgent/agentIntentRelevanceService.js` builds a per-message intent plan before the model sees tools. The gate receives the raw current merchant turn plus a small recent-message context for confirmations, not the full LLM prompt, so old summaries/RAG text cannot hijack the current tool scope. HR attendance questions are scoped to `hr.attendance_today`, agent-team questions are scoped to the agent manager tools, and implementation/debugging questions receive no business data tools.
- `services/aiAgent/agentToolGatewayService.js` is the controlled execution boundary. It validates agent tool permissions, applies write-conflict checks where a resource conflict key can be derived, executes the registered API tool, and writes audit entries through `agentAuditTrailService`. It also writes an `AGENT_INTENT_PLAN` audit entry for each CEO chat turn before tool execution, including the selected intent, primary tool, allowed tools, and raw intent message.
- `services/aiAgent/CEOAgent.js` routes native tool calls, legacy text tool calls, intent-gate repairs, and leaked DSML calls through the gateway. User-visible replies are stripped of internal syntax and fail with `AI_AGENT_TOOL_CALL_LEAK` or `AI_AGENT_EMPTY_REPLY` if the model cannot produce a real final answer; no synthetic assistant fallback is generated. The CEO chat path passes a structured task containing `description` (LLM prompt) and `currentMessage`/`intentMessage` (gate input).
- `agents/_shared/tool-registry.json` and `agents/manager-ceo/agent.json` must list every runtime tool the CEO template can receive, including `hr.attendance_today`, `company.snapshot`, `sales.revenue`, `customer.topBuyers`, and the order/product read tools. This keeps template validation aligned with `services/aiAgent/agentToolRegistry.js`.
- `services/aiAgent/aiChatService.js` persists chat sessions/messages to the existing `AIChatSession` and `AIChatMessage` tables on a best-effort basis, while keeping Redis working memory as the fast path. It also hides old assistant messages that contain internal tool syntax, passes only recent visible messages as intent context, and reminds the agent not to restart greetings inside an active session.
- `services/aiAgent/agentChatTranscriptService.js` must use the Prisma delegates generated for `AIChatSession`/`AIChatMessage` (`aIChatSession`/`aIChatMessage`) so durable transcript writes do not silently hit the broken lowercase aliases.
- `frontend/src/pages/admin/AIChatPage.tsx` filters any assistant message that still contains internal tool syntax so the UI never displays raw runtime instructions.

Regression coverage lives in `tests/services/agentNativeTooling.test.js`, including DSML parsing, HR attendance intent routing, current-turn gating with old HR summaries present, confirmation carry-over for agent creation proposals, irrelevant-tool denial, gateway execution from leaked text, and safe failure when the model never returns a user-facing answer.
