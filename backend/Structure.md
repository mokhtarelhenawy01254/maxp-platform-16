# System Structure & Architecture

### API Endpoints
No API endpoints were modified or added, but:
1. The backend endpoint `/api/v1/ai-image/model-config` (handled by `getModelConfig` in `aiImageController.js`) now has its `allowedModels` payload fully consumed by the newly introduced model selection dropdown in the AI Image Generator interface.
2. The backend template creation endpoint `/api/v1/whatsapp-templates/templates` (handled by `whatsappMetaTemplateController.createMetaTemplate`) was updated to propagate Meta's detailed API error payloads (including `error_user_title`, `error_user_msg`, and Meta subcodes) with the correct HTTP status code instead of swallowing them with a generic 500 status.
3. The backend authentication endpoints `/auth/login`, `/auth/me`, `/auth/companies` (handled by `getUserCompanies`), and `/auth/switch-company/:companyId` were updated to select and include the `roleRef` relation inside `userCompanies` queries, ensuring that role resolution prefers custom/assigned role keys (`uc.roleRef?.key || uc.role`) over the database default enum (`AGENT`), preserving administrative and owner access on page reload or switch. Additionally, `/auth/login` and `/auth/switch-company/:companyId` now load and return user permissions consistently via `permissionService.getUserPermissions`, and return the context-aware selected company object (including role and activeApps) to prevent frontend sidebar collapsing or inconsistency on reload/switch.
4. The backend endpoints `/api/v1/whatsapp/conversations` and `/api/v1/whatsapp/conversations/:jid/messages` (handled by `whatsappController.getConversations` and `whatsappController.getMessages` respectively) were updated to check and enforce user-specific number access permissions via `getUserAccessibleSessionIds` for non-admin accounts.
5. The WebSocket audience resolution inside `whatsappRealtimeAudienceService.js` was overhauled to construct precise target sets (including admins, leaders, and authorized agents/team members) and default `fallbackToCompany` to `false` for socket message event deliveries, stopping company-wide message leaks.
6. The backend query logic for `/api/v1/whatsapp-inbox/sessions` was updated inside `getUserAccessibleSessionIds` helper to restrict returned sessions to those with active assignments.
7. The workspace query logic `/api/v1/admin/whatsapp-numbers/workspace` was updated inside `numberAssignmentService.js` to ensure Meta Cloud provider sessions resolve to `CONNECTED` and to filter out soft-deleted sessions (where `isDeleted: true` is in metadata) to align with the Settings page.
8. The backend endpoint `/api/v1/whatsapp/sessions` (handled by `whatsappController.getSessions`) was updated to restrict returned sessions to only user-accessible sessions for non-admin roles (moderators/employees) using `getUserAccessibleSessionIds`.
9. The AI Service agent pipeline stages (`skills_pipeline.py` and `validate_reply.py`) were modified to support concurrent tool execution, tool arguments self-correction, strict Pydantic contract fallbacks, and output guardrail self-correction. Additionally, `client.py` and `skills_pipeline.py` were enhanced to support strict tool schemas, capture/propagate `reasoning_content` to stabilize DeepSeek V4 Flash tool calling, and parse XML-like DSML tool calling markup natively to prevent raw protocol leaks in chat sessions. Finally, `skills_pipeline.py` was refactored to use `build_user_content` from `src.context.multimodal`, fixing the customer image attachment pipeline for vision-capable models (like Gemini 2.5 Flash), resolved empty reply crashes causing `AI_SANDBOX_EMPTY_REPLY` downstream, updated `_format_tool_results` to correctly extract and format categories lists returned by the `category_list` tool, and expanded formatting to handle the `"results"` key (used by product search wrappers), single-product dictionaries (from `inventory_check`), and structured summaries for `offers_list_active`, `coupon_validate`, `order_lookup`, and `customer_info` tools. The `_normalize_openai_messages` method in `client.py` was also updated to sanitize tool call `arguments` fields, serializing Python `dict` objects to JSON strings, preserve `reasoning_content` and `reasoning` keys in the serialized assistant messages array to satisfy DeepSeek API schema requirements, and `_generate_openai_compat` was updated to omit the `tools` and `tool_choice` parameters entirely if `tool_choice == "none"` to prevent DeepSeek API 400 validation and completion failures during follow-up chat completions.
10. The Python `/chat` endpoint (`api/chat.py`) was updated to support `status: "escalated"` with optional `escalation` metadata.
11. A new `silentEscalationService.js` was introduced in the backend to manage Socket.IO events (`ai:escalation`) and DB `ActivityLog` creation for silent human handoffs.
12. The backend sandbox chat endpoint `/api/v1/ai-sandbox/chat` (handled by `aiSandboxController.sendChatMessage` / `runSelectedAgentInPython`) was updated to map `compiled_system_prompt` from the Python response to `result.compiledSystemPrompt`, enabling system prompt visualization in the Sandbox UI.
13. The backend endpoint `/api/v1/whatsapp/messages/upload-send` (handled by `whatsappRoutes.js`) was updated to support explicit `ptt` flag and override media classification to `'audio'` when file name is `'voice_note.webm'`, ensuring playable push-to-talk voice messages are delivered to WhatsApp.
14. The backend endpoint `/api/v1/whatsapp/messages/upload-send` MIME types whitelist was expanded to support common browser/client recording formats (`audio/wav`, `audio/x-wav`, `audio/wave`, `audio/x-pn-wav`, `audio/x-m4a`, `audio/aac`, `audio/x-aac`, `application/zip`, `application/x-zip-compressed`, `application/rar`, `application/x-rar-compressed`, `application/octet-stream`), and detailed console error logging was added to Multer's `fileFilter` for rejections.
15. The AI Service agent model resolution logic (`_resolve_agent_model` in `agent_registry.py`) was updated to prioritize the company-specific model override (`db_agent.model`) over the template's default model policy (`template.model_policy.get("default")`), ensuring company-level customizations are correctly respected.

### System Architecture
- **Vite Chunk Load Recovery & Cache Control Routing**: Overhauled the frontend root error boundary structure in `AdminAppBootstrap.tsx` to statically import the `ErrorBoundary` component, ensuring the application can capture module loading failures (due to deleted assets during production updates) and successfully execute chunk load recovery (automatic window reloads). Hardened the Nginx static assets mapping in `nginx_configs/maxp.online.conf` by adding strict Cache-Control headers (`no-cache, no-store, must-revalidate`) for the SPA `/` location blocks, preventing browsers and proxy CDNs from caching `index.html` and forcing them to fetch the most updated hashed asset references.
- **WhatsApp Workspace Responsive Overhaul**: Introduced container `:has()` layout overrides in `index.css` to dynamically strip container paddings and avoid double scrolls when browsing the `/whatsapp` path. Leveraged modern 2026 CSS layout patterns: View Transitions API for seamless sliding transitions, `@starting-style` entry animations for conversation cards/messages, `@container` queries for screen-width sensitive chat bubble sizing, and CSS-native Scroll-Driven Animations for header compression on scrolling. Added touch event swipe capture for mobile back-to-list navigation, responsive overlay trays for entry tools, themed container compatibility for the audio recorder component, sliding bottom sheet drawer configurations for the emoji picker, and touch swipe gestures (`Swipe-to-Archive`) for conversation cards in the chat list.
- Added **Silent Takeover & human-in-the-loop** event-driven pattern via Socket.IO: on AI failure (e.g. guardrail blocks or JSON parsing exhaustion), the thread is marked as needing human intervention, notifying moderators instantly without alerting the customer.
- Agent templates follow a **multi-file contract** pattern: `agent.json` (manifest) + `SOUL.md` (persona/workflow) + `TOOLS.md` (tool instructions) + `AGENTS.md` (handoff rules), assembled into a single XML `<agent_contract>` at runtime by `template_registry.py`.
- Unified **WhatsApp Auto-Assignment**: Unified incoming webhook message sync and background sweeps under a single advanced `WhatsAppAssignmentEngineService`, ensuring all incoming chats respect online status, workload capacity, working hours, and transactional locks. Additionally, corrected the candidate pool generation to prioritize configured employee lists (`routingUserIds`) over direct number owners in Round Robin and Shared Inbox modes.
- **Distributed Sweep Coordination**: Background monitor sweeps utilize PostgreSQL session-level advisory locks (`pg_try_advisory_lock`) to coordinate single-instance execution across PM2 cluster nodes.
- **Assignment-Relative SLA Cooldown**: Implemented a 5-minute cooldown and assignment-relative SLA timeout calculation based on `lastAssignedAt` to eliminate 60-second reassignment ping-pong loops between moderators.
- **GramJS Unhandled Rejection Alert Loop Isolation**: Added `isGramJsResolveError` helper in `recoverableUnhandledRejection.js` to identify and ignore `resolve() called for non-request instance` errors from the GramJS library, preventing an infinite feedback loop where unhandled rejections trigger Telegram alerts, which in turn generate new Telegram updates and trigger new errors.
