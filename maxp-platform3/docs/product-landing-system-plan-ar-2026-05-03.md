# خطة نظام صفحات هبوط المنتجات المصورة

**التاريخ:** 2026-05-03  
**الهدف:** تحويل تجربة صفحة Swan المصورة من prototype إلى نظام داخل MaxP، بحيث كل صفحة هبوط تكون مربوطة بشركة ومنتج حقيقيين، وتستخدم نفس مسار الطلبات والتحليلات.

## حالة التنفيذ الحالية

تم تنفيذ أول نسخة داخل النظام:

- موديل `ProductLandingPage` اتضاف في Prisma مع ربط مباشر بـ `Company` و`Product`.
- API عام يفتح الصفحة المنشورة بالـ slug ويرجع الصفحة + المنتج + الشركة.
- API إدارة محمي لعرض/إنشاء/تعديل/نشر/إيقاف صفحات الهبوط.
- storefront route `/store/lp/:slug` أصبح يقرأ من API، ويعرض stack صور موبايل، ثم form حقيقي في آخر الصفحة.
- الطلبات القادمة من الصفحة تحمل `landingPage` attribution في `Order.metadata` و`OrderItem.metadata`.
- صفحة إدارة أولية اتضافت تحت `/advertising/product-landing-pages` مع اختيار المنتج، توليد AI brief، توليد/إضافة/ترتيب الصور، معاينة موبايل، وحفظ/نشر.
- تم إنشاء تجربة محلية منشورة للمنتج `Local Resistance Band Set` على شركة `Local Affiliate Demo`.

نتيجة الاختبار المحلي:

- الرابط العام: `/store/lp/local-resistance-band-ai?companyId=cmoozcsmm0000vpwg4bzzno72`.
- الصفحة عرضت 6 صور، بدون horizontal overflow على viewport 430px.
- كل الصور lazy/eager اشتغلت بعد scroll.
- الفورم أنشأ طلبًا حقيقيًا من public orders API.
- عداد صفحة الهبوط وصل إلى `orders=2` بعد اختبارين.

## الفكرة الأساسية

صفحة الهبوط ليست بديلًا عن المنتج. هي واجهة تسويقية فوق منتج حقيقي:

- الشركة: `companyId`
- المنتج: `productId` أو `productSlug`
- المتغيرات: `variantId` عند اختيار المقاس/اللون
- الصور المصورة: slices مرتبة تحت بعض للموبايل
- الفورم: ينشئ طلبًا حقيقيًا من نفس public order API
- التحليلات: تسجل مصدر الزيارة والصفحة والمنتج

## التصميم الإداري المقترح

### مكان الصفحة في النظام

داخل قسم التسويق:

`Marketing -> Product Landing Pages`

أو عربيًا:

`التسويق -> صفحات هبوط المنتجات`

### شاشة القائمة

واجهة عملية كثيفة وليست تسويقية. أعلى الصفحة:

- زر `إنشاء صفحة هبوط`
- فلتر الحالة: مسودة، منشورة، موقوفة
- فلتر المنتج/التصنيف
- بحث بالاسم أو الرابط

الجدول يعرض:

- صورة مصغرة لأول slice
- اسم صفحة الهبوط
- المنتج المرتبط
- الحالة
- الرابط العام
- عدد الزيارات
- الطلبات
- معدل التحويل
- آخر تحديث
- أزرار: معاينة، تعديل، نسخ الرابط، إيقاف/نشر

### شاشة الإنشاء/التعديل

تقسيم الشاشة إلى عمودين:

1. يمين/يسار حسب اللغة: إعدادات الصفحة.
2. العمود المقابل: معاينة موبايل مباشرة داخل إطار هاتف.

الأقسام:

- **الربط:** اختيار الشركة تلقائيًا من جلسة المستخدم، ثم اختيار منتج حقيقي من منتجات الشركة.
- **المحتوى المصور:** رفع slices أو توليدها لاحقًا بالـ AI، مع ترتيب بالسحب، alt text لكل صورة، وتحديد أول صورة كـ priority.
- **نموذج الطلب:** اختيار الحقول المطلوبة، إظهار/إخفاء المحافظة والمنطقة والملاحظات، وطريقة الدفع الافتراضية.
- **النشر:** slug الصفحة، الحالة، رابط المعاينة، رابط الإنتاج.
- **التتبع:** UTM، Meta Pixel event name، source label مثل `product_image_landing`.
- **SEO بسيط:** title, description, OG image.

### تجربة المستخدم داخل الإدارة

1. يضغط `إنشاء صفحة هبوط`.
2. يختار المنتج من منتجات شركته.
3. النظام يسحب تلقائيًا السعر والصورة والمتغيرات.
4. يرفع أو يولد 4-8 صور slices.
5. يشوف معاينة موبايل مباشرة.
6. يضغط `حفظ كمسودة`.
7. يختبر الرابط.
8. يضغط `نشر`.
9. ينسخ الرابط للإعلانات أو Meta Ads.

## شكل واستايل الإدارة

الطابع: عملي، واضح، يشبه cockpit للتسويق، مش landing page داخل الإدارة.

- خلفية هادئة جدًا: أبيض/رمادي فاتح.
- Accent واحد واضح للإجراءات الأساسية: أخضر أو أزرق عميق حسب النظام الحالي.
- Cards قليلة ومسطحة بحدود خفيفة، بدون كروت داخل كروت.
- أيقونات للمعاينة، النسخ، النشر، الإيقاف، الترتيب.
- إطار هاتف ثابت للمعاينة، بعرض 390-430px.
- Tabs بدل صفحة طويلة: `المحتوى`، `الفورم`، `النشر`، `التحليلات`.
- حالات واضحة: Draft، Published، Paused.

## شكل صفحة الهبوط العامة

Mobile-first:

- لا Header ولا Footer المتجر العادي افتراضيًا.
- Stack صور كامل العرض، كل صورة لها `width/height/alt`.
- أول صورة eager، والباقي lazy.
- CTA sticky صغير بعد أول scroll.
- الفورم في آخر الصفحة.
- ملخص المنتج قبل الفورم: السعر، المقاسات، الألوان، التوفر.
- الإرسال يستخدم المنتج الحقيقي والمتغير الحقيقي.

Desktop:

- لا نحولها إلى صفحة ديسكتوب ضخمة.
- نعرض نفس عمود الموبايل في المنتصف مع خلفية خفيفة.
- الهدف أن تجربة الإعلان على الموبايل تفضل الأصل.

## Sprint 1: ربط حقيقي بدون AI Generator

**الهدف:** صفحة landing منشورة من الداتابيز ومربوطة بمنتج حقيقي.

المهام:

- إنشاء موديل `ProductLandingPage`.
- API داخلي للإدارة: list/create/update/publish.
- API عام: جلب landing page بالـ slug مع المنتج المرتبط.
- تعديل storefront route `/store/lp/:slug` ليقرأ من API بدل config ثابت.
- إنشاء order حقيقي من الفورم مع `landingPageId` في metadata/attribution.
- إضافة tests لعزل الشركة: لا يمكن فتح صفحة منتج من شركة أخرى.

التحقق:

- إنشاء landing لمنتج موجود داخل شركة.
- فتح الرابط العام.
- اختيار variant.
- إرسال طلب حقيقي في local seed/test.
- ظهور الطلب مربوط بالمنتج والشركة.

## Sprint 2: صفحة الإدارة

**الهدف:** يستطيع صاحب الشركة إنشاء وإدارة صفحات هبوط المنتجات.

المهام:

- إضافة route في frontend مثل `/marketing/product-landing-pages`.
- إضافة sidebar item في قسم التسويق.
- بناء شاشة القائمة.
- بناء شاشة الإنشاء/التعديل.
- إضافة معاينة موبايل مباشرة.
- إضافة رفع وترتيب الصور.

التحقق:

- إنشاء صفحة من منتج موجود.
- ترتيب الصور.
- حفظ مسودة.
- نشر.
- نسخ الرابط وفتحه من storefront.

## Sprint 3: تحسين التحويل والتحليلات

**الهدف:** الصفحة لا تكون شكل فقط؛ تقيس أداءها.

المهام:

- تسجيل view event للصفحة.
- تسجيل submit/start_checkout/order_created.
- Dashboard صغير: visits, orders, conversion rate.
- تخزين UTM/referrer/landingPageId مع الطلب.
- دعم duplication: clone landing page لمنتج آخر.

التحقق:

- زيارة الصفحة تزيد visits.
- الطلب يزيد orders.
- يظهر conversion rate.
- الطلب يحتوي source واضح.

## Sprint 4: AI/Design Workflow لاحقًا

**الهدف:** توليد أو تحسين الصور من داخل النظام.

المهام:

- زر `Generate slices`.
- Prompt مبني من بيانات المنتج.
- حفظ المخرجات كأصول للصفحة.
- اختيار style preset.
- إمكانية regenerate لصورة واحدة.

التحقق:

- توليد slices وحفظها.
- تعديل الترتيب.
- نشر صفحة جديدة بنفس الصور.

## مخاطر مهمة

- يجب منع أي Landing Page من عرض منتج لا يتبع نفس الشركة.
- لا نعتمد على fallback في production.
- الصور يجب أن تكون أصول منشورة وليست ملفات محلية فقط.
- الطلب يجب أن يحمل `productId` و`variantId` الصحيحين.
- صفحة الإدارة يجب أن تمنع النشر لو المنتج غير نشط أو الصور ناقصة.
- لا نبدأ بتوليد AI قبل تثبيت الربط والداتابيز والنشر.

## أسئلة قبل التنفيذ

1. هل نضعها في قسم `التسويق` باسم `صفحات هبوط المنتجات`؟
2. هل أول نسخة تحتاج رفع صور يدوي فقط، أم نضيف زر AI Generator من البداية؟
3. هل تريد الرابط العام يكون `/store/lp/:slug` فقط، أم أيضًا رابط قصير مثل `/l/:slug`؟
