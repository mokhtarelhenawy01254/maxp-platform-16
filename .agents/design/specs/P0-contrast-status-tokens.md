## 2. المستخدم/المهمة المتأثرة

كل بادج حالة في اللوحة في **الوضعين**: «تم التأكيد» · «قيد الانتظار» · «تم الشحن» · «ملغي» ·
تحذيرات الدفع · رسائل النجاح/الخطأ. التاجر المصري بيقراها في نهار عملي على موبايل — تباين 2.14:1
معناه نص شبه مخفي. وفي الوضع الغامق (اللي بيستخدمه بالليل) نفس المشكلة بالظبط.

## 3. الخيارات (قرار مطلوب)

### الخيار A — نُغمّق قيمة اللون نفسه (يُبقي الأبيض)
| التوكن | من | إلى |
|---|---|---|
| `--color-success` | `oklch(0.692 0.153 159.9)` | `oklch(0.545 0.145 159.9)` |
| `--color-warning` | `oklch(0.769 0.165 70.1)` | `oklch(0.585 0.150 66.0)` |
| `--color-destructive` | `oklch(0.637 0.208 25.3)` | `oklch(0.535 0.200 25.3)` |
| `--color-primary` | `oklch(0.581 0.229 263.9)` | `oklch(0.552 0.225 263.9)` |

**إيجابي:** صفر تغيير في الكود، والمستخدم ما يحسّش.
**سلبي:** الحالة في الوضعين بتصبح أغمق. في الغامق تحديدًا، توكن غامق على خلفية غامقة = **مشكلة
جديدة** (فشل آخر). 그래서 الخيار A لوحده **مش كافي** — لازم يتعمل مع الخيار C.

### الخيار B — نغيّر `*-foreground` من أبيض إلى داكن (يُبقي اللون)
```css
--color-success-foreground: oklch(0.20 0.045 159.9);
--color-warning-foreground: oklch(0.24 0.060 70.1);
--color-destructive-foreground: oklch(0.22 0.075 25.3);
```
**إيجابي:** الألوان تبقى حية كما هي.
**سلبي:** كل بادج فاتح + نص داكن — بكسل مختلف، وكل `statusRegistry` className محتاج مراجعة.

### 🆕 الخيار C — تعريفات غامقة منفصلة في `.dark` (لازم مع A أو B)
```css
.dark {
  --color-warning: oklch(0.706 0.150 70.1);   /* أفتح: نص غامق/فاتح يبقى مقروء */
  --color-success: oklch(0.682 0.140 159.9);
  --color-card: oklch(0.217 0.042 257.8);     /* مسجَّل أصلاً — المشكلة في usage مش التعريف */
}
```
**إيجابي:** الوضع الليلي يبقى ليه هوية بصرية خاصة، والتباين بيتحل في الوضعين مستقل.
**سلبي:** صيانة توكنز مضاعفة، ومخاطر drift بين الوضعين.

> **توصيتي (مش تنفيذ):** A + C معاً. الخيار B أوسع أثراً لأنه بيمس كل بادج في اللوحة، و
> `statusRegistry` فيه 22 استيراد.
