# Product Landing Public Runtime Fix - 2026-05-07

## Context

The live product landing admin at `/advertising/product-landing-pages` could load after authentication, but the public landing link generated by the admin failed in the browser with:

```text
getProductLanding is not a function
```

The public route in `ProductImageLandingPage` expected `storefrontApi.getProductLanding(...)` and `storefrontApi.trackProductLandingOrder(...)`, but the shared storefront API helper only exposed regular storefront/catalog/cart/order methods.

## Change

- Added `storefrontApi.getProductLanding(slug)` for `GET /api/v1/product-landings/public/:slug`.
- Added `storefrontApi.trackProductLandingOrder(slug, payload)` for `POST /api/v1/product-landings/public/:slug/order`.
- Both helpers preserve the storefront `companyId` query/header behavior used by path-scoped storefront pages.
- Added a regression test covering the public landing fetch, unpublished 404 handling, and landing-order tracking endpoint.
- Added a descriptive `alt` value to the product thumbnail in the landing-page admin editor.

## Verification

- Focused Vitest coverage: `src/utils/__tests__/storefrontApi.productLanding.test.ts`.
- Manual production finding remains expected until content is published: Swan's current `swan-sneaker-7` landing page is still `DRAFT` and has zero slices, so the backend public API should return `404` until the page is published with images.
