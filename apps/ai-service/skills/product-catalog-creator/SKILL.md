# product-catalog-creator

مهارة متخصصة لإنشاء وإضافة المنتجات إلى المتجر وقاعدة بيانات المخزون بدقة تجارية وهندسية عالية، استناداً إلى صور المنتجات المرفوعة، أو مواصفات الموردين، أو طلبات التاجر المباشرة.

---

## متى تُستخدم هذه المهارة
1. عندما يرفع التاجر صورة منتج أو عدة صور ويطلب إضافتها للمتجر أو المخزن.
2. عندما يطلب التاجر صراحة إنشاء صنف جديد ("أنشئ منتج جديد"، "أضف هذا الصنف للمخزن").
3. عند استيراد بضاعة جديدة وتحديد التكلفة وسعر البيع وهوامش الربح والكميات الافتتاحية.
4. عند الحاجة لتسجيل منتج بمتغيرات متعددة (مقاسات، ألوان، أو أوزان مختلفة).

---

## الأدوات المتاحة وطريقة استخدامها

### 1. product_create
- **الهدف:** الأداة التنفيذية لإنشاء المنتج وتخزينه في قاعدة بيانات المتجر والمخزون.
- **المعاملات الصريحة (Structured Parameters):**
  - `name`: اسم المنتج التجاري الواضح والجذاب (مثال: "قميص كتان كاجوال أبيض").
  - `price`: سعر البيع النهائي للعميل بالعملة المحلية (رقم موجب، مثال: 450.0).
  - `compare_price`: سعر البيع قبل الخصم إن وجد شطب ترويجي (مثال: 550.0).
  - `cost`: تكلفة شراء أو تصنيع القطعة لضبط هامش الربح الإجمالي (مثال: 220.0).
  - `stock`: الرصيد الافتتاحي في المخزن (مثال: 50).
  - `sku`: رمز تعريفي مميز للصنف (إذا لم يحدده التاجر، قم بتوليده بصيغة `PRD-CATEGORY-TIMESTAMP`).
  - `category_name`: اسم القسم أو التصنيف التجاري (مثال: "ملابس رجالي").
  - `images`: مصفوفة روابط الصور المرفوعة (تأكد من تضمين روابط الصور المرفوعة في الطلب).
  - `description`: وصف تسويقي موجز يوضح خامة المنتج ومميزاته واستخداماته.
  - `variants`: قائمة المتغيرات الفرعية (إن وُجدت مقاسات أو ألوان).
  - `status`: حالة المنتج ("PUBLISHED" للعرض المباشر أو "DRAFT" للمراجعة).

### 2. category_list
- **الهدف:** استعراض الأقسام والتصنيفات الحالية في المتجر لمطابقة القسم بدقة وتجنب تكرار أسماء التصنيفات.

### 3. product_search
- **الهدف:** التحقق السريع من عدم تكرار اسم المنتج أو كود الـ SKU مسبقاً في الكتالوج.

### 4. product_update_price
- **الهدف:** تعديل أو تحديث سعر الصنف إذا رغب التاجر في تصحيح السعر بعد الإنشاء.

## خطوات التنفيذ المنضبطة (Execution Protocol)

### الخطوة الأولى: استقراء بيانات المنتج والصورة المرفقة
- عند استلام صورة منتج مرفقة:
  - استنتج طبيعة الصنف ونوعه (ملابس، إلكترونيات، مستحضرات، أحذية، أدوات منزلية، إلخ).
  - صِغ اسماً تجارياً دقيقاً وموجزاً يعبر عن الصنف وخامته ومظهره.
  - حدد أو اقترح القسم المناسب (`category_name`).

### الخطوة الثانية: التدقيق المالي والتسعير
- إذا حدد التاجر سعر البيع والتكلفة، احسب هامش الربح الإجمالي:
  `هامش الربح = ((سعر البيع - التكلفة) / سعر البيع) * 100`
- إذا لم يحدد التاجر التكلفة، افترض هامش ربح تجاري قياسي للصنف (35% إلى 50%) واذكر ذلك بوضوح.
- إذا لم يحدد التاجر رصيد المخزون الافتتاحي، استفسر عنه أو عيّن قيمة مبدئية مع توضيح إمكانية تسويتها فورياً.

### الخطوة الثالثة: استدعاء أداة الإنشاء
- نفّذ استدعاء أداة `product_create` بالمعاملات الكاملة مع تضمين رابط الصورة في حقل `images`.

### الخطوة الرابعة: تقديم التقرير للتاجر في جدول ماركداون أنيق
اعرض نتيجة الإنشاء في جدول موجز وبيانات تليمتري دقيقة:

| البند | البيان |
| :--- | :--- |
| اسم المنتج | {name} |
| كود الصنف (SKU) | `{sku}` |
| التصنيف | {category_name} |
| سعر البيع | {price} ج.م |
| سعر التكلفة | {cost} ج.م |
| هامش الربح المتوقع | {margin}% |
| الرصيد الافتتاحي | {stock} قطعة |
| الحالة | `IN_STOCK` أو `متوفر` |

### الخطوة الخامسة: الإجراءات التالية المقترحة
- اعرض على التاجر خيارات مباشرة:
  1. إضافة مقاسات وألوان فرعية (Variants).
  2. ضبط حد تنبيه انخفاض المخزون (Reorder Point).
  3. تسليم المنتج لوكيل التسويق لبدء صياغة زوايا إعلانية وحملة ترويجية عبر استوديو التسويق.

---

## الممنوعات والقواعد الصارمة
1. ممنوع اختلاق أرقام عشوائية دون إيضاح افتراضها للتاجر.
2. ممنوع حفظ المنتج بدون كود SKU أو بدون تصنيف واضح.
3. ممنوع تجاهل الصورة المرفوعة؛ يجب دائماً إدراج رابط الصورة في مصفوفة `images`.
4. لا تستخدم الإيموجي أو العبارات التسويقية الفضفاضة، بل ركّز على الدقة المحاسبية والمخزنية.
