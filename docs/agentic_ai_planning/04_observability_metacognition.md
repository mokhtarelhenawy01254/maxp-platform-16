# 📊 المراقبة والوعي الذاتي وحوكمة التكاليف (Observability & Governance)

هذا المستند يفصل معمارية تتبع أداء الوكلاء (Telemetry)، والنقد الذاتي (Metacognition)، وإدارة التكلفة المالية ومحدد الميزانية، والتخزين الدلالي المؤقت (Semantic Cache) وتوجيه الموديلات في منصة **MaxP**.

---

## 📊 1. معمارية الـ Observability وتتبع العمليات

لضمان إزالة صفة "الصندوق الأسود" (Black Box) عن الوكلاء في الإنتاج، نطبق تتبعاً شجرياً للعمليات برمجياً بالاعتماد على معيار **OpenTelemetry** المفتوح وإرساله لأدوات التحليل (مثل Langfuse أو Arize Phoenix):

### أ. التتبع الشجري للعمليات (Trace Tree structure):
*   **الـ Trace:** يمثل العملية الكاملة لحل الطلب أو المحادثة ويحتوي على المعرف الفريد `traceId` والزمن الإجمالي وتكلفة المعاملة.
*   **الـ Spans:** تمثل الخطوات الفرعية المتداخلة (Nested Spans) المكونة للمعاملة:
    *   `Span 1 (RAG Retrieval)`: استرجاع البيانات دلالياً.
    *   `Span 2 (LLM Generation)`: استدعاء الموديل لتوليد كود التخطيط.
    *   `Span 3 (Tool Execution)`: استدعاء API خارجي لتأكيد حجز.

```typescript
export interface telemetrySpan {
  spanId: string;
  traceId: string;
  parentSpanId?: string;       // لتمثيل التداخل الشجري للخطوات
  spanType: 'LLM_CALL' | 'TOOL_EXECUTION' | 'RAG_RETRIEVAL' | 'CRITIQUE' | 'AGENT_DELEGATION';
  name: string;
  startTime: Date;
  endTime: Date;
  latencyMs: number;           // زمن استغراق الخطوة بدقة
  inputPayload: any;           // المدخلات الممررة
  outputPayload: any;          // المخرجات المستقبلة
  tokenCount?: {
    promptTokens: number;
    completionTokens: number;
    totalCostUsd: number;
  };
  errorMessage?: string;
}
```

## 🧠 2. الوعي الذاتي وفصل كتل التفكير (Metacognition)

يقوم الوكيل بمراقبة وتقييم مسار تفكيره الخاص قبل إخراج الردود للعملاء عبر آليتين:

1.  **فصل التفكير عن الاستجابة (Separation of Thoughts vs. Actions):**
    *   يُجبر الموديل في سياقه البرمجي على إخراج كتلة تفكير تفصيلية مخفية عن العميل البشري (Thought Block) يحلل فيها الخيارات المتاحة والاعتماديات.
    *   يكتب النتائج النهائية في كتلة مخرجات مستقلة تماماً (Action/Response Block) وهي التي تُرسل فقط للمستخدم.
2.  **حلقة التقييم والنقد الذاتي (Self-Critique Engine):**
    *   قبل إتمام الإجراء، يتم مقارنة المخرجات المقترحة حتمياً مع قوانين الحظر الممرضة في `SOUL.md` (مثل منع تقديم وعود شحن غير دقيقة أو خصومات غير معتمدة).
    *   إذا اكتشف النموذج تعارضاً، يطلق عملية تصحيح تفكير وتعديل المخرج تلقائياً (Self-Correction) لتلافي الخطأ.

## 💸 3. حوكمة وتحسين التكلفة المالية للمستأجرين (Cost Governance)

لمنع الفواتير الهائلة وحماية الخوادم، نطبق 3 طبقات حماية مالية ديناميكية:

### أ. محدد ميزانية الشركة الصارم (Multi-Tenant Token Budgeting):
*   يتم قراءة وتسجيل استهلاك التوكنز والأسعار الفعلية وتخزينها في قاعدة البيانات لكل مستأجر (`companyId`).
*   إذا تخطى المتجر الميزانية المالية اليومية أو الشهرية المحددة، تحظر برمجيات الخادم الوسيطة (Middleware) استدعاء الـ LLM فوراً وتعلق نشاط الوكيل وتلجأ للردود اليدوية وتنبه المدير البشري.

### ب. التخزين المؤقت الدلالي (Semantic Caching Layer):
*   تكامل محرك الكاش الدلالي (Redis Vector Search) للبحث في الأسئلة المتطابقة دلالياً للمشترين بنسبة Cosine Similarity > 95%.
*   في حال التطابق الدلالي، يتم إرجاع الرد المحفوظ فوراً من الكاش بزمن استجابة أقل من 50ms وتكلفة $0، دون إجهاد النماذج الذكية.

### ج. موجه الموديلات الذكي (Model Registry Routing):
*   توزيع العمليات حركياً بناءً على تعقيد المهمة لتوفير التكاليف:
    *   **المهام البسيطة والروتينية** (التصنيف، الصياغة البسيطة، الترحيب) ➡️ تُوجه لـ `gemini-2.5-flash` الرخيص والسريع جداً.
    *   **المهام فائقة التعقيد** (تخطيط الـ DAG، وحل التعارضات، والنقد الذاتي) ➡️ تُوجه للـ `gemini-2.5-pro` القوي والدقيق.
