# مراجعة تصميم الموبايل لمنصة MaxP

مهارة تشغيلية: تفحص الموقع جزء جزء على الموبايل، تسجل كل عيب في سجل النتائج، تصلح، تعيد الفحص، وتحدّث السجل — عشان نرجع للنتايج في كل جولة إصلاحات لاحقة.

## 1) القاعدة الذهبية

**كل عيب بيتسجل في `references/findings-log.md` قبل ما يتصالح.** الإصلاح من غير تحديث السجل = مش خالص. السجل هو الذاكرة المشتركة بين الجلسات.

## 2) تجهيز جلسة الفحص (أوامر جاهزة)

استخدم playwright-cli بمحاكاة موبايل حقيقية (ده اللي مثبت إنه شغال في المشروع):

```bash
# فتح جلسة موبايل (iPhone 14 = 390px، touch، UA موبايل)
playwright-cli -s=mob open --device="iPhone 14" https://swan.maxp.online/

# فحص التمرير الأفقي (أخطر عيب) — نفذ على كل صفحة بعد فتحها
playwright-cli -s=mob eval "document.documentElement.scrollWidth + ' vs ' + window.innerWidth"

# لقطة شاشة + قراءتها بصريًا (اقرأها بأداة Read بعد الحفظ في جذر المساحة)
playwright-cli -s=mob screenshot --filename=mob-NN-<page>.png

# فحص حجم أزرار الـ CTA الظاهرة أسفل الشاشة
playwright-cli -s=mob eval "JSON.stringify((function(){const els=[...document.querySelectorAll('button,a')].filter(b=>(b.innerText||'').trim() && b.offsetParent); return els.slice(0,10).map(b=>({txt:(b.innerText||'').trim().slice(0,30), h:Math.round(b.getBoundingClientRect().height), w:Math.round(b.getBoundingClientRect().width)}));})())"

# اختبار تجميد الـ main thread (بعد الصفحات الثقيلة)
playwright-cli -s=mob eval "(function(){var t=Date.now(); var s=0; for(var i=0;i<2e6;i++) s+=i; return Date.now()-t;})()"

# فحص «البوكس جوه بوكس» — كثافة التداخل والمساحة الفعلية للمحتوى
# (أي نص مهم عرضه الفعلي < 70% من الشاشة على 390px = عيب — الهدف 85%+)
playwright-cli -s=mob eval "JSON.stringify((function(){function chain(el){let d=0,e=el; while(e && e!==document.body){const s=getComputedStyle(e); if((s.borderRadius!=='0px'||s.boxShadow!=='none') && s.backgroundColor!=='rgba(0, 0, 0, 0)') d++; e=e.parentElement;} return d;} const texts=[...document.querySelectorAll('p,td,li,h1,h2,h3')].filter(x=>x.innerText && x.innerText.length>30 && x.offsetParent); const worst=texts.map(x=>({w:Math.round(x.getBoundingClientRect().width), nest:chain(x), t:x.innerText.slice(0,30)})).sort((a,b)=>a.w-b.w)[0]; return JSON.stringify({screen: innerWidth, worstContentW: worst? worst.w:0, pct: worst? Math.round(worst.w*100/innerWidth):0, nesting: worst? worst.nest:0});})())"
```

**فخوث معروفة:**
- Git Bash بيكسر بعض أنماط grep فيها `/` (زي `grep -oE '/my-apps/...'`) — استخدم `grep -E 'url:'` أو استخرج اللينكات من الـ DOM بـ eval.
- مستخرج اللينكات من الـ DOM أدق من السطرجي: `JSON.stringify([...new Set([...document.querySelectorAll('a')].map(a=>a.getAttribute('href')))])`.
- لو اللقطة طلعت «جاري التحميل...» استنى `sleep 3` وخد لقطة تانية.

## 3) معايير الفحص (الملخص السريع)

المرجع الكامل الموثق: **اقرأ `references/standards-2026.md`** قبل أي مراجعة كبيرة (تحديث 2026-09-01). الملخص:

- **Core Web Vitals 2026:** LCP ≤ 2.5s، INP ≤ 200ms (الرسمي بدل FID)، CLS ≤ 0.1 — على بيانات مستخدمين حقيقيين موبايل.
- **وصولية WCAG 2.2:** أهداف لمس ≥ 24px (مفضل 44px)، تباين نص ≥ 4.5:1، focus visible، نموذج بـ labels دائمة ورسائل خطأ نصية.
- **تشيك ليست الموبايل:** صفر تمرير أفقي في 375/360/414، خط مدخلات ≥ 16px (يمنع iOS zoom)، احترام `env(safe-area-inset-*)` مع النوتش، lazy-load صور بأبعاد محددة، `:active` خلال ≤ 100ms، dark mode بيحافظ على التباين.
- **عربي/RTL:** logical properties بدل left/right، line-height 1.6–1.8، bidi سليم في النماذج، اختبر القوائم بعد الانعكاس.
- **CSS 2026:** Container Queries، `:has()`، scroll-driven animations، View Transitions — بدل مكتبات JS.

## 4) سير العمل القياسي (جزء جزء)

1. **اختار الجزء الجاي** من قائمة الأجزاء في `references/findings-log.md` (قسم «أجزاء تحت المراجعة»).
2. **افتح كل صفحة** في الجلسة الموبايل: فحص overflow → لقطة شاشة → اقراها بصريًا → فحص أهداف اللمس → سكرول كامل للصفحة (بداية/نص/نهاية — عيوب الـ padding بتظهر في النهاية).
3. **سجل كل عيب فورًا** في `references/findings-log.md` بمعرف جديد:
   ```
   ### MOB-0XX 🔴/🟡/🟢 <عنوان قصير>
   - **الجزء:** <اسم الجزء/الصفحة>
   - **العيب:** <وصف دقيق — إيه اللي بيظهر وما المفروض يحصل>
   - **الدليل:** mob-NN-<page>.png
   - **الإصلاح المقترح:** <كود/تغيير محدد>
   - **الحالة:** 🔴 مفتوح
   ```
   الشدة: 🔴 حرج (بيكسر الاستخدام/الفلوس) — 🟡 متوسط (تناسق/وضوح) — 🟢 بسيط (تشطيب).
4. **الإصلاح:** طبّق + كوميت + push (الـ deploy بيتابع نفسه) — وحدّث الحالة في السجل: `🟡 متصلح — commit <hash>، مستني إعادة فحص`.
5. **إعادة الفحص:** بعد الـ deploy افتح نفس الصفحة بنفس الأوامر + لقطة قبل/بعد — وحدّث: `✅ متصلح ومتحقق <تاريخ>`.
6. **نقل لتحديث السجل:** الملف ده هو اللي نرجعله في كل جولة — افتحه أول كل جلسة مراجعة.

## 5) قواعد الإصلاح في هذا المشروع تحديدًا

- **RTL أولًا:** استخدم `margin-inline/padding-inline/inset-inline` — ممنوع left/right ثابتة. أي هيدر/صف جديد اتأكد إنه انعكس صح.
- **الشريط السفلي الثابت (storefront bottom nav):** أي صفحة فيها الشريط لازم `padding-bottom` على المحتوى ≥ ارتفاع الشريط + safe-area. دي وقعتنا رقم 1 (MOB-001).
- **قاعدة «عمق بوكس واحد» على الموبايل (MOB-015):** ممنوع كارت جوه كارت في موبايل — المحتوى الداخلي يندمج في الأب بفاصل `border-t`. استخدم أمر قياس التداخل في §2 على كل صفحة: أي نص مهم عرضه الفعلي أقل من 70% من الشاشة (390px) = عيب مسجل. دي ملاحظة المختار نفسه — أولوية.
- **حظر حجز مساحات دائمة للأدوات أحادية الاستخدام:** أي أداة أو وظيفة تستخدم مرة واحدة فقط في الجلسة (مثل اختيار المنتج، تبديل الجلسات، الفلاتر الأولية) ممنوع حجز عمود أو لوحة ثابتة لها (تسرق 25%-50% من الشاشة). تُدمج في شريط الأدوات العلوي (Combobox / Dropdown) أو درج منبثق (Drawer / Modal) عند الحاجة فقط.
- **مكافحة الشروحات والنصوص الإنشائية (Show, Don't Tell):** ممنوع حشو التطبيق التشغيلي واللوحة بنصوص تسويقية أو شروحات إرشادية تحت العناوين والأزرار. استخدم تسميات حركية مقتضبة وواضحة، واعتمد Tooltips للتلميحات لتوفير المساحة الرأسية للعين وتقليل العبء المعرفي.
- **استغلال مساحة العمل والموبايل (85%+ Utilization):** مساحة الإنتاج والعمل الحقيقي (مثل الشات التفاعلي أو لوحة التعديل) يجب أن تستحوذ على الأغلبية العظمى من الشاشة. في الموبايل، تجنب نقل المستخدم قسرياً بين تابات منفصلة لإجراء خطوة واحدة مرتبطة.
- **حظر الهوامش الميتة الخارجية (Zero Dead Margins):** في لوحات التحكم واستوديوهات العمل، ممنوع ترك هوامش رمادية ميتة ناتجة عن `Layout.tsx` (`p-4 md:p-6`). يجب تفعيل `<Layout fullWidth>` و `shouldRemovePadding` لتصل مساحة العمل إلى حواف الشاشة مباشرة (`p-1.5 sm:p-2`).
- **التوافق الرأسي مع شاشات اللابتوب (Laptop Viewports <= 768px):** الارتفاع المتاح على اللابتوب (1366x768 أو 1080p) هو 550-650px فقط. ممنوع استخدام صور معاينة ضخمة `aspect-[4/3]`; الارتفاع الأقصى للكانفاس هو `h-36 sm:h-44 object-cover`. ممنوع تكديس المدخلات الفردية عمودياً فوق زر الأكشن; يجب دمج حقل الميزانية/السعر أفقياً في شريط إطلاق الحملة `[ Input ] + [ Primary CTA ]`. وتوضع القواعد والإعدادات الثانوية في دروور مطوي افتراضياً.
- **كروت تفاعلية بدل جدران النصوص:** ردود الأيجنت الطويلة التي تحوي زوايا أو خطط تسويقية يجب تحويلها لكروت تفاعلية (Generative Action Cards) قابلة للنسخ أو التطبيق المباشر بضغطة زر.
- **تناسق اللغة:** الداتا اللي بتتعرض للعميل العربي لازم عربي (أسماء منتجات/مدن/labels) — لو الداتا نفسها ناقصة ترجمتها دي مشكلة داتا بتترفع للتجار، والحل البرمجي fallback عربي.
- **لا تعرض معرفات داخلية** (cart_xxx / cuids) للمستخدم — اعرض رقم طلب بشري.
- **التصميم سيستم المشروع:** سياق التصميم الموثق في `.agents/context/` (حمّله بـ load-context.mjs قبل أي شغل تصميم) — النظام Restrained/OKLCH/Tailwind v4.
- **اختبر على 390px (iPhone 14) وذَكّر نفسك إن 360px أضيق** — الشريط العلوي المزدحم بيتكسر على 360.
- **بعد أي إصلاح UI في المتجر:** اعيد فحص مسار الشراء كامل (هوم → شوب → PDP → سلة → دفع) مش الصفحة المصلحة بس.

## 7) بروتوكول جولة الإصلاحات (لما نرجع للنتايج)

1. افتح السجل، جمّع كل العيوب 🔴 المفتوحة للجزء المستهدف.
2. رتبها: عيوب الكود الأول (padding/اتجاه/معرفات) — بعدين عيوب الداتا (ترجمة/تنظيف URLs) محتاجة قرار.
3.صلح دفعة واحدة لكل جزء → كوميت واحد وصفي (`fix(mobile): <الجزء> — <العيوب>`) → push.
4. بعد الـ deploy: **إعادة فحص الجزء كامل** بالبروتوكول في §4، حدّث كل معرف لـ ✅، والتقط لقطات بعد.
5. لو العيب سببه الداتا (مش الكود): سجله في قائمة «محتاج قرار/داتا» ومتعتبروش متصلح.
