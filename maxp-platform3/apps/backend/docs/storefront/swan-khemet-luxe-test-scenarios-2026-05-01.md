# خطة اختبار متجر Swan / KHEMET LUXE

التاريخ: 2026-05-01
النطاق: قالب KHEMET LUXE المطبق على متجر Swan/Flora من أول زيارة حتى صفحة الشكر، مع اختبار تجربة المستخدم، سلوك الشراء، أدوات المتجر، الأداء، والتحويل.

## الهدف

هذه الخطة ليست مجرد Smoke Test. الهدف تشغيل المتجر كأنه تحت حملة إعلانية فعلية:

- التأكد أن المستخدم يستطيع التنقل بدون Refresh إجباري.
- التأكد أن زر "ضيفيه للسلة" يضيف المنتج ويفتح السلة مباشرة.
- التأكد أن مسار الشراء من الإعلان إلى الطلب واضح وسريع.
- قياس جودة تجربة الموبايل والكمبيوتر.
- كشف مشاكل السرعة، الصور، التحميل، النصوص، والثقة.
- اختبار أدوات البيع: السلة، الأب سيل، البحث، الفلاتر، المقاسات، المراجعات، الكوبونات، الدفع، والشكر.

## بوابات القبول

لا نعتبر المتجر جاهزا إلا إذا تحققت النقاط التالية:

- لا توجد أخطاء JavaScript ظاهرة في Console أثناء السيناريوهات الأساسية.
- كل روابط الهيدر والموبايل تنقل للصفحة المطلوبة بدون الحاجة لعمل Refresh.
- زر إضافة للسلة يفتح السلة أو ينقل المستخدم للسلة حسب السلوك المطلوب في القالب.
- لا يوجد Horizontal Scroll على الموبايل.
- كل أزرار اللمس الأساسية لا تقل عن 44px تقريبا.
- صفحة المنتج تعرض السعر، الصور، المقاسات، CTA، الشحن/الاستبدال، والمراجعات بوضوح.
- السلة واضحة وكبيرة بما يكفي، وبها CTA ظاهر للدفع وأب سيل غير مزعج.
- الوصول من صفحة المنتج إلى الدفع يتم في أقل من 4 خطوات بعد اختيار المقاس/الكمية.
- لا يتم إنشاء طلب حقيقي على Production إلا لو تم التصريح بذلك صراحة.
- أهداف الأداء الأولية:
  - Mobile LCP أقل من 2.5 ثانية قدر الإمكان.
  - CLS أقل من 0.1.
  - لا توجد صور Hero أو Product كبيرة بدون ضغط/أبعاد ثابتة.
  - لا يتم تحميل سكريبتات غير ضرورية قبل تفاعل المستخدم.

## الأجهزة والبيئات

يتم الاختبار على:

- موبايل صغير: 390x844.
- موبايل متوسط: 430x932.
- تابلت: 768x1024.
- كمبيوتر: 1366x768.
- كمبيوتر واسع: 1440x900.
- شبكة Fast 3G / Slow 4G.
- أول زيارة بدون Cache.
- زيارة متكررة مع Cache.
- حالة مستخدم بسلة قديمة محفوظة.
- حالة مستخدم بدون Cookies/LocalStorage.

## شخصيات المستخدم

### U1 - زائر من إعلان

يدخل مباشرة على صفحة منتج. يريد أن يرى المنتج، السعر، المقاس، الثقة، ثم يضيف للسلة بسرعة.

### U2 - متسوق يتصفح

يبدأ من الهوم، يفتح الأقسام، يستخدم البحث والفلاتر، ثم يدخل أكثر من منتج قبل الشراء.

### U3 - مستخدم متردد

يراجع المقاسات، الشحن، الاستبدال، المراجعات، ويحتاج رسائل طمأنة واضحة قبل الدفع.

### U4 - مستخدم لديه سلة

يرجع للموقع وسلته بها منتجات. يتوقع استمرار السلة وإمكانية التعديل والدفع.

### U5 - مستخدم شبكة ضعيفة

يفتح من الموبايل على اتصال بطيء. الصور والسكريبتات يجب ألا تمنع الشراء.

## P0 - سيناريوهات حرجة

هذه السيناريوهات تمنع إطلاق أو استمرار حملة إعلانية إذا فشلت.

### P0-01 فتح صفحة منتج من إعلان

الأجهزة: Mobile + Desktop
المدخل: رابط منتج مباشر مثل `/product/kotshy-soan`

الخطوات:

1. افتح رابط المنتج في جلسة جديدة.
2. راقب تحميل الصفحة حتى تصبح قابلة للتفاعل.
3. تأكد من ظهور الصورة، الاسم، السعر، المقاسات، CTA.
4. افتح Console وتأكد من عدم وجود أخطاء حرجة.

المتوقع:

- لا توجد شاشة بيضاء أو Loader عالق.
- معلومات المنتج الأساسية تظهر فوق الطية على الموبايل أو قريبة جدا منها.
- CTA واضح بدون تداخل مع الهيدر أو الصور.

### P0-02 إضافة للسلة من صفحة المنتج

الأجهزة: Mobile + Desktop
المدخل: صفحة منتج بها مخزون.

الخطوات:

1. افتح صفحة المنتج.
2. اختر المقاس/اللون إذا كان مطلوبا.
3. اضغط "ضيفيه للسلة".
4. راقب سلوك الصفحة بعد الإضافة.

المتوقع:

- المنتج يضاف فعلا للسلة.
- عداد السلة يزيد.
- السلة تفتح مباشرة أو ينتقل المستخدم للسلة حسب المتفق عليه.
- لا يحتاج المستخدم لعمل Refresh.
- لا يتكرر المنتج مرتين بسبب Double Click سريع.

### P0-03 منيو الهيدر لا تحتاج Refresh

الأجهزة: Mobile + Desktop
المدخل: أي صفحة منتج.

الخطوات:

1. افتح صفحة منتج.
2. اضغط كل رابط من روابط الهيدر: كل الأحذية، الكوتشيات، الفلات، العروض.
3. راقب URL والمحتوى.
4. استخدم Back/Forward.

المتوقع:

- يتغير المحتوى مع الرابط مباشرة.
- لا تبقى صفحة المنتج ظاهرة بعد تغير الرابط.
- Back/Forward يعيدان المحتوى الصحيح.
- لا يوجد فقدان للسلة أثناء التنقل.

### P0-04 مسار الدفع من المنتج

الأجهزة: Mobile + Desktop
المدخل: صفحة منتج.

الخطوات:

1. اختر المنتج والمقاس.
2. اضغط إضافة للسلة.
3. من السلة اضغط إتمام الطلب.
4. املأ بيانات العميل ببيانات اختبار.
5. توقف قبل إرسال الطلب الحقيقي على Production.

المتوقع:

- مسار واضح من المنتج إلى Checkout.
- ملخص الطلب مطابق للسلة.
- السعر، الشحن، الخصم، والإجمالي واضحين.
- رسائل التحقق تظهر بجانب الحقول الخطأ.

### P0-05 السلة والتعديل

الأجهزة: Mobile + Desktop
المدخل: سلة بها منتج واحد على الأقل.

الخطوات:

1. افتح السلة.
2. زد الكمية.
3. قلل الكمية.
4. احذف المنتج.
5. أضف المنتج مرة أخرى.

المتوقع:

- الإجمالي يتحدث فورا.
- لا توجد قفزات Layout مزعجة.
- الحذف يوضح حالة السلة الفارغة وCTA للعودة للتسوق.
- السلة لا تغلق أثناء تعديل الكمية إلا إذا كان ذلك مقصودا.

### P0-06 Checkout validation

الأجهزة: Mobile + Desktop
المدخل: Checkout.

الخطوات:

1. افتح Checkout بسلة صالحة.
2. حاول المتابعة بدون بيانات.
3. أدخل رقم هاتف ناقص.
4. أدخل عنوان ناقص.
5. اختر/غير المحافظة إن وجدت.

المتوقع:

- لا يتم قبول بيانات ناقصة.
- رسائل الخطأ عربية ومفهومة.
- لا تضيع بيانات المستخدم بعد ظهور خطأ.
- لا يحدث Reload كامل غير ضروري.

### P0-07 صفحة الشكر

الأجهزة: Mobile + Desktop
المدخل: طلب اختبار على بيئة غير Production أو بعد تصريح.

الخطوات:

1. أكمل طلب اختبار.
2. افتح صفحة الشكر.
3. راجع رقم الطلب وملخص المنتجات.
4. اضغط Continue shopping أو أي CTA تال.

المتوقع:

- تظهر رسالة نجاح واضحة.
- رقم الطلب أو مرجع الطلب ظاهر.
- لا تعرض الصفحة معلومات ناقصة أو متضاربة.
- توجد خطوة تالية مفيدة: متابعة التسوق، واتساب، أو تتبع الطلب.

## P1 - سيناريوهات التحويل والبيع

### P1-01 زائر إعلان إلى شراء سريع

الخطوات:

1. افتح منتج مباشر.
2. اقرأ أول شاشة خلال 5 ثوان.
3. حدد هل السعر، العرض، المقاس، والثقة واضحين.
4. أضف للسلة.
5. اذهب للدفع.

المتوقع:

- لا يحتاج المستخدم للبحث عن الزر.
- الجملة التسويقية لا تغطي على السعر/CTA.
- الشحن والاستبدال واضحان قبل الدفع.

### P1-02 الأب سيل داخل السلة

الخطوات:

1. أضف منتجا للسلة.
2. افتح السلة.
3. راجع المنتجات المقترحة.
4. أضف منتجا مقترحا.
5. راجع الإجمالي.

المتوقع:

- الأب سيل ظاهر لكن لا يزاحم CTA الدفع.
- إضافة المقترح لا تغلق السلة بطريقة مربكة.
- المنتج المقترح له صورة وسعر وCTA واضح.

### P1-03 البحث

الخطوات:

1. افتح البحث من الهيدر.
2. ابحث بكلمة منتج موجودة.
3. ابحث بكلمة غير موجودة.
4. افتح منتج من النتائج.
5. أغلق البحث بالماوس وبزر Escape إن مدعوم.

المتوقع:

- نتائج تظهر بسرعة.
- لا توجد نتائج مكررة أو صور مكسورة.
- حالة "لا توجد نتائج" مفيدة وتعرض CTA للتسوق.
- البحث لا يكسر Scroll الصفحة.

### P1-04 الفلاتر والفرز

الخطوات:

1. افتح `/shop`.
2. اختر قسم الكوتشيات.
3. غيّر الفرز.
4. طبق فلتر سعر/مقاس إن وجد.
5. امسح الفلاتر.

المتوقع:

- URL يعكس الفلاتر بشكل قابل للمشاركة.
- النتائج تتغير بدون Refresh إجباري.
- لا تختفي المنتجات كلها بسبب فلتر غير واضح.
- زر Clear filters ظاهر عند وجود فلاتر.

### P1-05 مراجعة المقاسات

الخطوات:

1. افتح صفحة منتج.
2. اضغط Size guide.
3. راجع هل المقاسات مفهومة للمستخدم المصري.
4. أغلقه.
5. أكمل إضافة للسلة.

المتوقع:

- المقاسات واضحة ولا تحتاج تكبير مؤلم على الموبايل.
- إغلاق المودال سهل.
- لا يضيع اختيار المقاس بعد فتح الدليل.

### P1-06 كوبون الخصم

الخطوات:

1. افتح Checkout بسلة صالحة.
2. أدخل كوبون غير صحيح.
3. أدخل كوبون صحيح إذا متاح في بيئة الاختبار.
4. احذف الكوبون.

المتوقع:

- رسالة الكوبون الخطأ واضحة.
- الخصم الصحيح ينعكس في Order summary.
- لا يتغير الإجمالي بشكل غير مفهوم.

## P2 - تجربة المستخدم والتصميم

### P2-01 أول 5 ثوان على الموبايل

الاختبار:

- هل المستخدم يعرف أين هو؟
- هل المنتج واضح؟
- هل الزر الأساسي واضح؟
- هل السعر والعرض يظهران قبل التمرير الطويل؟
- هل يوجد عنصر ثقة قريب: شحن، استبدال، دفع عند الاستلام؟

المتوقع:

- الصفحة تقود المستخدم للشراء بدون شرح زائد.
- لا يوجد نص كبير يأخذ مساحة أهم من المنتج والCTA.

### P2-02 قابلية القراءة بالعربي

الاختبار:

- راجع أسماء المنتجات.
- راجع أزرار CTA.
- راجع رسائل الأخطاء.
- راجع نصوص الشحن والاستبدال.
- راجع صفحة الشكر.

المتوقع:

- النصوص طبيعية ومفهومة.
- لا توجد عبارات مترجمة حرفيا.
- صيغة المؤنث/المخاطبة مناسبة لو جمهور المتجر نسائي.
- لا توجد كلمات إنجليزية بلا داع إلا لو جزء من البراند.

### P2-03 موبايل Thumb Reach

الخطوات:

1. امسك واجهة الموبايل كاستخدام حقيقي.
2. افتح المنيو، البحث، السلة.
3. أضف منتج، عدل كمية، ادفع.

المتوقع:

- الأزرار الأساسية قريبة من الإبهام.
- لا توجد أزرار صغيرة جدا.
- Sticky CTA لا يغطي محتوى مهم.

### P2-04 Desktop scanning

الخطوات:

1. افتح الهوم.
2. افتح shop.
3. افتح PDP.
4. راجع هل العين تفهم الأولويات بسرعة.

المتوقع:

- لا توجد مساحات فارغة مبالغ فيها.
- المنتج والسعر والعروض لها أولوية بصرية.
- الفلاتر لا تختفي أو تتكدس.

### P2-05 حالات التحميل

الخطوات:

1. افتح الموقع على Slow 4G.
2. راقب Skeleton/Loader.
3. انتقل بين الصفحات.
4. افتح الصور.

المتوقع:

- لا تظهر الصفحة بيضاء لفترة طويلة.
- الصور لها أبعاد ثابتة تمنع القفز.
- Loader لا يعلق بعد فشل طلب API.

## P2 - الأداء والسرعة

### PERF-01 Lighthouse Mobile

الصفحات:

- Home.
- Shop.
- Product.
- Cart.
- Checkout.
- Thank you.

المقاييس:

- Performance score.
- LCP.
- CLS.
- TBT.
- حجم الصور.
- عدد طلبات JS/CSS.

المتوقع:

- لا توجد صورة Product/Hero بحجم غير منطقي.
- Critical CSS/JS لا يحمل كل شيء دفعة واحدة إن أمكن.
- Fonts لا تسبب تأخير واضح.

### PERF-02 تنقل داخلي متكرر

الخطوات:

1. من صفحة منتج افتح shop.
2. افتح sale.
3. ارجع لمنتج.
4. افتح cart.
5. كرر 20 مرة بسرعة معتدلة.

المتوقع:

- لا يحدث Memory leak واضح.
- لا تتضاعف Event listeners.
- لا تتوقف الأزرار عن العمل.
- السلة لا تفقد حالتها.

### PERF-03 ضغط سريع على الأزرار

الخطوات:

1. اضغط Add to cart مرتين بسرعة.
2. اضغط زيادة الكمية بسرعة.
3. اضغط Checkout مرتين.

المتوقع:

- لا يتكرر الطلب أو المنتج بشكل خاطئ.
- الأزرار تظهر Loading/Disabled أثناء العملية.
- لا يتم إرسال بيانات مكررة.

## P3 - حواف ومشاكل محتملة

### EDGE-01 منتج بدون مخزون

المتوقع:

- CTA يتحول لحالة غير متاح.
- لا يمكن إضافته للسلة.
- يوجد اقتراح بديل إن أمكن.

### EDGE-02 منتج بدون صورة

المتوقع:

- يظهر Placeholder محترم.
- لا ينكسر Layout.

### EDGE-03 قسم فارغ

المتوقع:

- تظهر حالة Empty واضحة.
- يوجد CTA للرجوع لكل المنتجات.

### EDGE-04 فشل طلب API

المتوقع:

- تظهر رسالة خطأ مفهومة أو fallback.
- لا تتعطل الصفحة بالكامل.

### EDGE-05 اختلاف العملة/الشحن

المتوقع:

- الأسعار واضحة.
- الشحن يظهر في المكان المناسب ولا يفاجئ المستخدم في آخر خطوة.

### EDGE-06 Back/Forward بعد إضافة للسلة

المتوقع:

- لا تتكرر الإضافة.
- السلة تظل صحيحة.
- الصفحة تعرض المحتوى المناسب للURL.

## Checklist لكل صفحة

### Home

## قرار Go / No-Go

### Go

- كل P0 ناجح.
- لا توجد مشاكل تمنع الإضافة للسلة أو الدفع.
- لا توجد مشكلة تنقل تحتاج Refresh.
- تجربة الموبايل واضحة بدون تداخل.

### Conditional Go

- مشاكل P2 فقط في الشكل أو النصوص.
- الأداء يحتاج تحسين لكن الشراء لا يتعطل.

### No-Go

- Add to cart لا يعمل أو لا يفتح السلة.
- الهيدر يغير URL فقط بدون تغيير الصفحة.
- Checkout لا يقبل بيانات صحيحة.
- السلة تفقد المنتجات.
- الصفحة الأساسية تحمل ببطء شديد أو تبقى بيضاء.
