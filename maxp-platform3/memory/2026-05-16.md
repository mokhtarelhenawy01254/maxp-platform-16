## Wofod Duplicate Order Fix

### Problem
Wofod AI was creating duplicate orders when customers changed order details (e.g., product color). Investigation confirmed:

- **ORD-960497-206** (color: بيج) was created first
- **ORD-076667-209** (color: أسود) was created ~2 minutes later for the same customer in the same conversation
- The `lastCreatedOrder` signature check didn't catch it because the color changed → different signature
- Layer 3 phone/total match caught it but only marked as DUPLICATE_ORDER instead of preventing creation
- The original (ORD-960497-206) was later trashed

### Fix Applied
Added `findRecentOrderInConversation` guard in `confirmedOrderExecutionService.js`:
- Before creating any order, checks if conversation metadata already has a `lastCreatedOrder` within the duplicate window (60 min default)
- If yes, returns early with a message saying the order is already registered
- Uses existing `extractLastCreatedOrderFromMetadata` and `loadConversationMetadata` helpers

### Deployment

- SCP'd to production `/var/www/backend2/services/aiAgent/confirmedOrderExecutionService.js`
