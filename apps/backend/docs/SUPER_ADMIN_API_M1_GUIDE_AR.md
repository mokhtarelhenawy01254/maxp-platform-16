# دليل واجهة برمجة تطبيقات السوبر أدمن — المرحلة م1 (Super Admin API Phase M1)

## 1. نظرة عامة والمعمارية (Architecture Overview)

تم بناء **Super Admin API (المرحلة م1: القراءة الكاملة + البنية التحتية)** لتمكين الإدارة المركزية والوكلاء الأذكياء (Autonomous Agents) من استعلام وتصفح كافة بيانات ومنظومات منصة MaxP بدقة فائقة وبأعلى معايير الأمان وعزل البيانات.

### المبادئ الهندسية الأساسية:
1. **امتداد نظام المفاتيح الموحد**:
   - تم البناء بالكامل فوق نظام المفاتيح الحالي في `apps/backend/middleware/externalApiAuth.js`.
   - لا يوجد نظام مفاتيح منفصل أو مكرر؛ جميع المفاتيح الموجودة في جدول `TaskExternalCredential` (بما فيها المفاتيح الـ 952 القائمة وسكوبات `tasks:read/write`) تواصل عملها دون أي انقطاع أو كسر للتوافقية الرجعية.
2. **كتالوج القدرات الديناميكي (Dynamic Capability Catalog)**:
   - الربط المباشر مع جدول `ai.agent_tool_catalog` عبر خدمة `apps/backend/services/capabilityCatalogSyncer.js`.
   - تفعيل تلقائي لكافة أدوات القراءة (`read operations`) مع حصر الكتابة (`write operations`) في مسارات مسودة تتطلب موافقة صريحة.
   - توليد مواصفة OpenAPI 3.0.3 بشكل ديناميكي ومباشر من الكتالوج عبر `/api/v1/admin-api/openapi.json`.
3. **حماية الخصوصية وحظر تسريب بيانات العملاء الأفراد (Zero-PII Redaction)**:
   - تم تطبيق طبقة حماية وتصفية صارمة عبر `apps/backend/utils/piiSanitizer.js`.
   - يتم حجب وحذف أي حقل يخص عميلاً فردياً (مثل: `customer_name`, `phone`, `email`, `address`, `password`, `recipient_phone`, `shippingAddress`) من كافة الردود.
   - الاستثناء الوحيد المصرح به هو اسم الشركة/المتجر (`company_name` / `tenant_name`) حصرياً لحاملي سكوب `admin:tenants:read` أو `*`.
4. **حدود المعدل الذكية (Sliding Window Dynamic Rate Limiting)**:
   - طلبات القراءة على مسارات `/admin-api/*`: **120 طلب / دقيقة**.
   - طلبات التعديل والكتابة: **20 طلب / دقيقة**.
   - المسارات القديمة: **60 طلب / دقيقة**.
5. **سجل التدقيق المتكامل (Audit Logging)**:
   - تسجيل كافة عمليات الوصول مع السكوبات والمفتاح والـ IP والنتائج في جدول التدقيق ومسار `/api/v1/admin-api/audit`.

## 2. المسارات المتاحة (Endpoints)

المسار الأساسي: `/api/v1/admin-api`
الترويسة المطلوبة للمصادقة: `x-api-key: <YOUR_API_KEY>`

### 2.1 التوثيق والكتالوج (Documentation & Catalog)
| المسار | الطريقة | السكوب المطلوب | الوصف |
|---|---|---|---|
| `/docs` | `GET` | بدون مفتاح أو بمفتاح | واجهة توثيق تفاعلية داكنة (OLED 2026 SaaS Cockpit) أو رد JSON عند طلب `Accept: application/json` |
| `/openapi.json` | `GET` | بدون مفتاح أو بمفتاح | مواصفة OpenAPI 3.0.3 ديناميكية متوافقة مع وكلاء الذكاء الاصطناعي |
| `/capabilities` | `GET` | بدون مفتاح أو بمفتاح | استعراض القدرات المتاحة وحالة ترخيص كل قدرة للمفتاح الحالي |
| `/health` | `GET` | عام (بدون مفتاح) | فحص صحة الخدمة وجاهزية قاعدة البيانات ومعدلات الذاكرة والـ Uptime |
| `/audit` | `GET` | `admin:audit:read` أو `*` | استعلام سجل التدقيق المفلتر حسب المسار والتاريخ والمفتاح |

### 2.2 مجالات القراءة الـ 17 الأساسية (Core Read Domains)
| المجال | المسار | السكوب المطلوب | وصف البيانات المعادة |
|---|---|---|---|
| التحليلات | `GET /analytics` | `admin:analytics:read` | إجماليات المنصة، عدد الطلبات، الإيرادات المجمعة، معدل النمو |

| الاشتراكات | `GET /subscriptions` | `admin:subscriptions:read` | خطط المنصة والشركات المشتركة وحالات التجديد والانتهاء |

| المستخدمون الإداريون | `GET /users` | `admin:users:read` | موظفو ومسؤولو المنصة (مع حجب كلمات المرور والبيانات الشخصية) |
| الشركات والمستأجرون | `GET /tenants` | `admin:tenants:read` | بيانات المستأجرين والشركات مع السماح فقط باسم الشركة |

### 2.3 المسار الديناميكي لأدوات الكتالوج الإضافية (Dynamic Fallback)
| المسار | الطريقة | السكوب المطلوب | الوصف |
|---|---|---|---|
| `/:domain` | `GET` | `admin:<domain>:read` | أي مجال إضافي معرف في `ai.agent_tool_catalog` (مثل `governance`, `catalog`, إلخ) يتم توجيهه تلقائياً واستخراجه من الكتالوج وقاعدة البيانات دون كتابة كود يدوي |

## 3. هرمية السكوبات والصلاحيات (Hierarchical Scopes)

يدعم نظام الفحص الصلاحيات الهرمية الشاملة لتسهيل الإدارة:
- `*`: وصول كامل وشامل لكافة مسارات النظام والقراءة والكتابة.
- `admin:*`: وصول كامل لكافة مسارات الـ Super Admin API.
- `admin:*:read`: صلاحية قراءة لكافة مجالات الـ Super Admin API الـ 17 والكتالوج الديناميكي.
- `admin:*:write`: صلاحية كتابة لكافة مجالات الـ Super Admin API.
- `admin:<domain>:*`: وصول كامل (قراءة وكتابة) للمجال المحدد (مثل: `admin:orders:*`).
- `admin:<domain>:read`: صلاحية قراءة محددة لنطاق معين (مثل: `admin:analytics:read`).
