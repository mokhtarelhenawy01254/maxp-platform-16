# تقرير تحليل الإلغاءات - 2026-05-03

## الهدف

إضافة تقرير جديد داخل تقارير الطلبات يساعد الإدارة على معرفة أسباب الإلغاء ومراجعة الطلبات الملغاة من مساحة الطلبات.

## المسارات

- الواجهة: `/analytics/orders/cancellations`
- القائمة الجانبية: تقارير الطلبات -> تحليل الإلغاءات
- الباك إند: `GET /api/v1/analytics/cancellations`

## مصدر البيانات

- المصدر الأساسي لسبب الإلغاء هو `OrderStatusHistory.reason` عند انتقال الطلب إلى `CANCELLED`.
- إذا لم يوجد سبب في سجل الحالة، يستخدم التقرير `Order.notes` أو `GuestOrder.notes` كـ fallback.
- التقرير يجمع الطلبات العادية `Order` وطلبات الضيف `GuestOrder`.
- يتم منع التكرار عند ظهور نفس الطلب في سجل الحالة وفي fallback الطلب الحالي الملغى.

## مخرجات الـ API

يرجع endpoint:

- `summary`: عدد الإلغاءات، الطلبات العادية، طلبات الضيف، القيمة المفقودة، متوسط قيمة الطلب، عدد الأسباب المسجلة وغير المسجلة.
- `reasonBreakdown`: أكثر أسباب الإلغاء النصية مع العدد والنسبة والقيمة المفقودة.
- `categoryBreakdown`: تصنيف عام للأسباب مثل طلب العميل، تعذر التواصل، مشكلة مخزون، مشكلة شحن.
- `dailyTrend`: عدد الإلغاءات يوميا داخل الفترة.
- `orders`: آخر الطلبات الملغاة للمراجعة مع رابط `/orders/workspace?order=:id`.
