# Storefront Quick View Modal Rich HTML Description Rendering Fix

## Issue Summary
In the storefront quick view modal (`QuickViewModal.tsx`), when previewing a product (such as on `https://ameerelle.maxp.online/shop`), rich HTML descriptions generated by the rich text editor (Quill) were rendered directly as plain text string nodes `{description}` instead of parsed HTML. This exposed raw markup tags (e.g. `p class="ql-align-center"><br></p><p class="ql-align-center"><strong>...</strong></p>`) to customers. In RTL contexts, the mixed English tag tokens and Arabic text caused severe bidi text jumbling.

## Root Causes
1. **Raw Text Interpolation**: `QuickViewModal.tsx` rendered `{description || ...}` inside a `<div className="prose prose-sm ...">` instead of using `dangerouslySetInnerHTML={{ __html: sanitizeStorefrontHtml(description) }}`.
2. **Missing Visibility Check**: Empty paragraphs or whitespace-only HTML markup (e.g. `<p><br></p>`) could render empty space instead of triggering the fallback "no description" localized placeholder.

## Solution Applied
- **`QuickViewModal.tsx`**:
  - Imported `sanitizeStorefrontHtml` from `../utils/html` and `sanitizeProductCopy` from `../utils/productCopy`.
  - Defined `sanitizedDescription = sanitizeStorefrontHtml(description)` and `hasVisibleDescription = Boolean(sanitizeProductCopy(description))`.
  - Safely injected sanitized HTML using `dangerouslySetInnerHTML={{ __html: sanitizedDescription }}` when visible content is present.
  - Retained localized fallback message (`لا يوجد وصف متوفر لهذا المنتج.` / `No description available for this product.`) when no visible description is available.
- **Unit Testing**: Added regression unit tests in `QuickViewModal.test.tsx` verifying proper sanitized HTML rendering without raw tag leakage and fallback handling.
