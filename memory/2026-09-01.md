## فحص وإصلاح مشكلة بطء السيرفر وتوقف الـ API (Axios timeout 30s)
- **الأعراض:** بطء شديد في الـ APIs (طلبات تستغرق 265 ثانية) وأخطاء `timeout of 30000ms exceeded` في المتصفح، وسقوط فحص الصحة `/api/v1/health` وتوقف `getPublicSettings`.
- **السبب الجذري:**
  1. عدم تفعيل `idle_in_transaction_session_timeout` و `statement_timeout` في PostgreSQL (كانا 0/معطلين)، مما تسبب في بقاء اتصالات المعاملات معلقة في حالة `idle in transaction`.
  2. استهلاك حوض اتصالات PgBouncer بالكامل (`default_pool_size = 30`) بسبب المعاملات العالقة مما جعل الطلبات تنتظر حتى `query_wait_timeout = 30s` وتفشل.
  3. عدم توافق `MAX_CONCURRENT_QUERIES (80)` مع `DATABASE_CONNECTION_LIMIT (25)` في Prisma مما سبب تراكم الطلبات في طابور محرك Prisma الداخلي.
- **الإصلاحات:**
  1. ضبط `idle_in_transaction_session_timeout = '20s'` و `statement_timeout = '30s'` في قاعدة بيانات PostgreSQL وإنهاء المعاملات المعلقة.
  2. توسيع حوض PgBouncer: `default_pool_size = 60`، `max_db_connections = 120`، `min_pool_size = 10`، `reserve_pool_size = 10`، وتفعيل `client_idle_timeout = 60`.
  3. محاذاة `MAX_CONCURRENT_QUERIES` و `DATABASE_CONNECTION_LIMIT` إلى 40 في `apps/backend/services/sharedDatabase.js` لمنع الاختناق.
  4. تحسين `healthCheck` و `checkModelIntegrity` للاتصال التلقائي بدلاً من إرجاع Disconnected فوراً.
  5. معالجة `null memberId` في `superAdminController.getActiveTimer`.
- **النتيجة:** استجابة فورية للفحص الصحي في **8ms** والـ Meta Pixel API في **170ms** بدون أي تأخير.
