# تعديل طلبات المسوق اليدوية وظهور المنتجات - 2026-05-03

## الهدف

تبسيط تجربة المسوق بحيث لا يرى في القائمة الجانبية صفحات منتجات مستقلة لا تضيف قيمة، وجعل إنشاء طلب العميل هو المكان الأساسي لاختيار منتجات الشركة، مع تحكم الشركة في ظهور كل منتج للمسوقين.

## ما تم

- إزالة روابط `كتالوج منتجات الشركة` و`المنتجات` من القائمة الجانبية للمسوق.
- تغيير تسمية إجراء المسوق إلى `طلب جديد للعميل`.
- جعل صفحة إنشاء الطلب على الموبايل أقرب لتطبيق موبايل بثلاث خطوات واضحة: المنتجات، السلة، بيانات الطلب.
- جعل منتجات الشركة تظهر داخل إنشاء الطلب للمسوق بشرط السماح لها من إعدادات المنتج.
- إضافة سياسة ظهور المنتج للمسوقين داخل إعدادات عمولة المنتج:
  - يظهر لكل المسوقين.
  - مخفي عن كل المسوقين.
  - يظهر لمسوقين محددين فقط.
- منع الطلبات من الخلفية أيضا إذا حاول مسوق طلب منتج مخفي أو غير مخصص له.
- جعل قوائم منتجات المسوق القديمة واستيراد المنتج تحترم نفس سياسة الظهور حتى لو تم الوصول لها مباشرة.

## السيناريوهات التي تمت تغطيتها

- المسوق لا يرى روابط الكتالوج أو المنتجات في القائمة الجانبية.
- المسوق الذي لديه صلاحية إنشاء طلب يرى رابط `طلب جديد للعميل`.
- صفحة طلب العميل تعرض منتجات الشركة المتاحة فقط للمسوق.
- المنتج المخفي عن كل المسوقين لا يظهر ولا يمكن طلبه عبر API.
- المنتج المحدد لمسوقين بعينهم يظهر للمسوق المسموح له فقط، ويتم رفض غيره.
- استيراد منتج للمسوق يرفض المنتجات المخفية أو غير المتاحة له.
- صفحة الطلب على الموبايل لا تصبح صفحة طويلة عشوائية، بل تتحرك بين المنتجات والسلة والدفع.

## التحقق

- اختبارات backend المستهدفة نجحت: `enhancedOrdersAffiliatePolicy.test.js` و`affiliateService.paymentMethod.test.js`.
- اختبارات frontend المستهدفة نجحت: sidebar وManualOrder وCheckoutColumn.
- `npm run build` في frontend نجح.
- `npm run type-check` لم يصبح نظيفا بسبب أخطاء TypeScript كثيرة موجودة على مستوى المشروع وليست محصورة في هذا التغيير.

## ملاحظات لاحقة

- قبل النشر يفضل تجربة حساب شركة فعلي مع مسوقين اثنين: مسوق مسموح له بمنتج محدد ومسوق غير مسموح له.
- الأفضل لاحقا نقل سياسة ظهور المنتج إلى تبويب مستقل إذا كبر إعداد العمولة والظهور أكثر من اللازم.
